# Canonically equivalent search input

On Alden 0.3.203, a project-scoped controlled source lookup found `면접 준비` but returned no facts for the same decomposed Hangul query. The decomposed spelling also reached the embedding callback unchanged. In a real installed owned-stdio MCP window with unchanged source versions, the NFC and NFD forms of `왕돈가스 평생 무료` returned different entities/proofs. The original source was present in both real results; the live result is query inconsistency, not proof that all decomposed queries return nothing.

Collection retrieval now applies NFC after validating the original query length, before lexical tokens, query-word grounding, latest selection and dense query encoding. Shared graph FTS token extraction also applies NFC before its existing case-folding/token rules. This keeps canonical spellings consistent across those search branches. It does not rewrite the caller's original input, source bytes, stable IDs, stored versions, embeddings or relationships.

NFC performs canonical composition. The new step does not apply compatibility folding; for example, the controlled embedding callback retains `①` while composing Hangul. Existing separate typo/compatibility normalization paths keep their existing behavior. Python documents the distinction between canonical NFC and compatibility NFKC. [Python 3.11 unicodedata documentation](https://docs.python.org/3.11/library/unicodedata.html#unicodedata.normalize)

The original wire/query length limit is checked before composition. An oversized decomposed request remains rejected even when its composed form would be shorter. Canonical equivalence is therefore an accepted-query behavior, not a bypass of input budgets.

The new controlled failures reproduce the original source/proof mismatch and the decomposed embedding input. Regression coverage checks identical scoped responses, a newer same-ID source in another project, unchanged database bytes, compatibility-character preservation, the original length bound and shared tokenizer equivalence. Both forms of an explicit latest-publication query must retain publication selection ahead of body preference.

The 151 collection and 104 graph tests pass; the final retrieval/MCP and installed/runtime results are recorded in private task outputs `query-nfc-20261021/`. The installed comparison uses the same project allowlist, a foreign-project rejection, an owned subprocess and before/after source-version signatures. No global host registration or independent semantic truth follows from that transport check.

The separate named-source ranking candidate is not enabled by this correction. Its original composed title query still requires the pending preference review/holdout/promotion work. Its historical source-bound artifact must be explicitly rebased and reverified before use against this changed retrieval dependency; the manifest guard must not be bypassed.
