# Alden 0.3.72 — 지식 그래프의 본문 근거 분리

같은 파일명과 “경로만 색인한 파일. 본문은 읽지 않았습니다.”라는 안내가 내용 중복과 E5 의미 연결의 근거로 통과하던 문제를 수정했다. 자료·구조 관계·원본 계보와 기존 검색 벡터는 유지하며, 본문 근거가 없는 기록의 의미 연결만 제외한다.

## 적용 경로

공통 규칙 `source-content-evidence-v2`는 현재 버전과 결속된 검색 투영의 `kind: metadata`, 명시적인 `content_indexed: false/0`, 전체 본문이 미열람 안내인 경우를 구분한다. 실제 설명 속에 안내문을 인용한 문서는 그 문장만으로 제외하지 않는다. 선언이 없다는 이유로 실제 내용·정확성·동일성을 인증하지 않는다.

의미 연결은 기존 현재 버전·권한·원본 SHA·보존 텍스트 검증을 먼저 수행하고, 이미 검증된 보관 기록의 미열람 선언도 확인한다. 실제 표본에서는 두 허브의 `content_indexed: 0`이 검색 투영에서 빠져 있어 추가 보강이 필요했다. 원본 파일 경로를 따라 열지 않고 보관된 canonical JSON만 기존 읽기 예산과 SHA 보호 안에서 사용한다. E5 벡터의 형식·프로필·단위 길이 검증과 같은 프로젝트 쌍 제한은 유지한다.

품질 확인은 원문 블롭을 읽지 않는 별도 관찰이다. 현재 검색 투영에서 확인 가능한 제외 수량과 이름·안내문 일치를 별도로 표시한다. 원문에만 있는 선언의 전체 수량이나 의미 정답을 이 집계로 인증하지 않는다. 개발 감사 schema3, 제품 품질 schema2와 새 정책 결속을 사용하며 이전 모호한 보고서를 0건 완료로 표시하지 않는다. 화면의 의미 연결도 새 정책·근거 SHA·제외/오류 수량 결속을 확인한다. 빈 표시 범위의 근거 SHA 누락도 재현·수정했다.

## 실제 관찰과 검증

5개 허용 프로젝트의 26,625현재 소속·26,623문서·48,355관계를 확인했다. 동일 수량의 별도 현재 읽기 트랜잭션에서 기존 문자열 663그룹이 본문 텍스트 후보136그룹과 메타데이터 이름·안내문527그룹으로 구분됐다. 투영 기준 제외4,921버전은 메타데이터만 있는4,861개와 미열람 안내60개다. 이 수치는 삭제·병합·확정 중복·원본 파일 바이트 동일성 판정이 아니다.

실제 집중 표본의 노드3개를 유지한 채 의미 연결 후보1→0을 확인했다. 제외는 투영 선언1개와 보관 기록 선언2개, 검증 오류0개였다. 이는 이 표본의 잘못된 연결 억제이며 전체 군집 품질·힘/방향의 정답 검증은 아니다. 기존 대규모 개요에는 계산·후보 예산과 부분 범위의 한계가 계속 적용된다.

3개의 내용 후보 오류, 빈 범위 결속 누락1건, 보관 선언 누락2건을 실패로 재현했다. 최종 pinned Python160검사, UI658검사·타입, native127·strict Clippy가 통과했다. 요청한 GPT-6 Web/xhigh 병렬 구현과 별도2기록 모델 평가를 실제 모델 메타데이터·패키지 SHA와 결속했다. 첫 독립 검토의 누락/차단 주장은 대응하는 실제 거절 출력이 없어 확인된 승인 제한으로 취급하지 않았고, 당시 보고서를 보존했다. 후속 검토는 보호 원본 없이 제공된 근거만 평가했다. 사람의 정답이나 전체663그룹의 독립 판정으로 사용하지 않는다.

여러 품질 감사를 같은 측정 프로세스에서 수행한 뒤 의미 연결을 실행한 첫 표본은 peak RSS 보호로 중단됐다. 예산을 올리지 않고 실제 제품처럼 별도 요청 프로세스에서 검증했다. 4.60초와약103MB의 후속 표본 관측은 다른 조건의2초 관측과 성능 비교하지 않는다. 전체 앱 FPS·GPU·배터리·RAM 개선은 미측정이다.

0.3.72/runtime `d15c29a962c3efe5868a03ebc97a64ed03090930`을 canonical 빌드·설치했다. 후보의 실제 읽기 전용 native14상태/28PNG·두 크기 품질 버튼이 성공했고 두 품질 PNG를 직접 검수했다. 설치64파일/모드·strict deep ad-hoc 서명과 독립0.3.71복구63파일을 대사했다. 설치 직후 설정3·대상7·정책2·모델 listener·음성 이력과 수집/검색7표 해시는 동일했다. 설치본의 native14상태/28PNG와 실제 두 크기 품질 버튼도 성공했고 추가2품질PNG를 직접 검수했다. 설치 CLI 전체 조회는 같은26,625소속/48,355관계·본문 후보136/메타데이터527그룹, 실제 집중 표본은 같은3노드/후보0/제외3/검증 오류0이었다. 실행 소스 [CI38182695701](https://github.com/twoimo/alden/actions/runs/38182695701)의 네 작업이 모두 성공했다. 설치 후 감사·CLI 실행 뒤에도 설치64파일/모드/서명·복구본·모든 보호 구간의 해시가 동일했고 기존 그래프 실험2파일과 별도 가역 병합 후보를 보존했다. 설치 primary가 정확한 번들에서 running인 것도 확인했다. 최종 증거와 단계별 실패는 작업 공간의 `outputs/source-eligibility-20261012/`에 보존했다.
