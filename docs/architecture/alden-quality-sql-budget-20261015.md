# Alden 0.3.120: interrupt quality SQL with its request

A quality scan previously checked cancellation, elapsed time and scan budgets between rows. SQLite could scan/sort an entire result before yielding its first row, so a cancelled request continued that SQL work. The read-only audit now checks the same request budget every 1,000 SQLite VM instructions on its two owned connections. It restores the original failure instead of leaking a generic SQLite `interrupted` error, refuses success even if an inner SQL fallback swallowed interruption, and clears both handlers before connections close.

The public report, SQL filters/order, source/cache binding, metadata/normalization checks, semantic policyv6, mapping/cache settings and row/byte/10-second budgets are unchanged. These VM checks do not forcibly interrupt OS blocking I/O, long UDFs or lock waits, and do not promise 50 ms response or an exact 10-second wall-clock limit. Verified retained-annotation inspection is a separate path; this change concerns the ordinary collection quality audit.

## Verification

- Three meaningful regressions failed before the respective fixes: cancellation and deadline each finished a300-row real SQLite view/sort first; a caught SQLite interruption could otherwise become success. The final focused quality/action suite passes 98 tests using synthetic isolated stores, including handler cleanup and existing source/permission/byte-budget behavior.
- On a frozen snapshot of 26,625 current memberships and 48,355 relations, all six final counterbalanced fresh-process runs produced identical public JSON apart from elapsed time. The two derived snapshots were individually pinned and exported through SQLite backup/quick_check, not raw WAL-file copies; cross-store version/hash bindings remain required.
- The benchmark has n=3 per variant. It is not a representative p95, cold/warm, energy or whole-app measurement, and no speedup is claimed. RSS includes reclaimable mapped pages, not just private heap.
- Actual permitted live-data source and candidate quality APIs complete successfully with identical public report hashes. An owned diagnostic callback observes execution within the SQL progress handler, returns cancellation and receives `quality_cancelled` without partial counts. A separate deliberately narrow 10 ms audit budget returns `quality_time_budget`. These probes do not change the user's emergency latch and do not prove physical UI/worker cancellation.

## Rejected proposals and retained limits

The row-name mapping proposal retained all results and passed95tests but its approximately 3.5 percent CPU median difference varied across n=3 paired trials; it was rejected. Expanding the collection mapping from 256 MiB to 1 GiB also retained results, but median RSS including file-backed pages rose from 488,210,432 to 683,229,184 bytes with modest variable timing differences; it was rejected and the original mapping restored.

The initial harness compared JSON-loaded lists to raw tuple-bearing reports and failed equality. Their normalized public JSON was identical; both the initial failure and corrected comparisons remain recorded. The first canonical check omitted the build's signing environment and failed; the same check with `OPENKAKAO_SIGN_IDENTITY=-` passes. Neither mismatch was resolved by weakening a product gate or rebuilding unchanged sources.

The earlier 119 initial 10-second quality failure remains a reliability limit. This patch improves when cancellation/deadline checks can run inside SQLite, not the completed scan's workload or guaranteed p95. Independent semantic/identity/time gold, selected-node useful labels, physical primary/tray/voice/Retina, wider host/MCP/acquisition, RAM-admitted multimodal models, real DPO/worker proof, current diagrams and signed/notarized/production release remain unfinished.

Astra reviewed only supplied guard code and its connection/check contract. Its conditional fallback finding was reproduced and fixed. This is not independent repository inspection; the earlier label/abort-reader source-read holds remain pending after automatic review could not determine request security. The earlier supplied-document annotations are provisional model judgments, not human gold.
