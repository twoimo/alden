# Alden 0.3.93 — Desktop 파일과 후속 질문

기존 대화 화면에서 사진과 문서를 따로 선택하고 같은 대화로 보낼 수 있다. 원문 파일 바이트를 private 저장소에 보존한 뒤 기존 문서 파서로 텍스트를 읽는다. 파일 수신, 해석, 추론 입력과 답변 확정을 구분하며 읽지 못한 자료를 읽었다고 표시하지 않는다.

기존 4-field 입력은 그대로 받는다. 선택적 `files`는 `name`, `mime`, `data`만 허용하고 경로·역할·실행 명령은 입력으로 받지 않는다. 실제 파싱은 파일명 suffix와 내용에 따르며 브라우저 MIME 힌트는 저장 정체성으로 신뢰하지 않는다. filename·정규화된 MIME·내용 SHA·크기를 요청 payload에 결속한다. 파일 없음과 빈 files 목록은 기존 요청 ID를 재사용할 수 있다. 완료된 동일 요청은 재해석·추론·메시지 추가 없이 원래 답변을 반환한다.

현재 첨부를 우선하고 같은 대화의 최근64개 완료 첨부 요청 안에서 고유한 이전 첨부를 고른다. 취소·실패·철회·다른 대화는 제외한다. 현재와 이전 사진/문서 합계4개·20MiB, 문서 개별5MiB와 사진 개별8MiB 한도를 적용한다. 64개 요청 밖을 전량 탐색했다고 주장하지 않는다.

문서는 TXT/MD/CSV/JSON/코드 등 텍스트, DOCX/XLSX/PPTX, PDF/RTF/DOC를 기존 판독기로 해석한다. PPTX/PDF는50장/쪽, ZIP은256항목/해제20MiB, 추출 텍스트는16,000바이트 한도다. OCR·문서 이미지 의미·Excel 수식 재계산을 지원한다고 표시하지 않는다. 파서는8초 한도의 소유 프로세스이며 취소 시 해당 프로세스만 회수한다. 출력과 stderr를 각각64,000/4,096바이트로 제한한다. 총 프로세스 RSS·배터리 한도나 개선은 미측정이다.

파일 저장 디렉터리0700/파일0600, regular file·단일 링크·소유자·바이트 길이·해시·읽기 전후 stat을 확인한다. 이름을 문서 파서 argv에 넣지 않는다. 추출된 자료는 원격과 로컬 두 어댑터에 외부 근거로 명시하며 코드·문서 내부 명령을 실행하지 않는다. 전달하는 전체 문서 맥락은 JSON 인코딩 후11,000바이트 이하로 줄이고 실제 excerpt SHA·parsed text SHA·누락·잘림을 기록한다. 원문 내용과 파일 바이트는 generation metadata에 넣지 않는다.

확정된 source request/turn/metadata를 추론 전과 답변 commit 트랜잭션에서 대사한다. 준비된 자료와 이력의 digest를 요청 ID에 영속 결속해 pending 재시도가 조용히 다른 맥락을 사용하지 못하게 한다. 파일 파싱 중 최신 턴이 들어오면 추론 전에 거절한다. 이미 외부 모델로 전송한 바이트를 철회로 회수했다는 보장은 없다.

source 구현·단위/통제 회귀·실제 패키지/설치·물리 사용의 검증 상태는 부모 workspace의 `outputs/assistant-files-20261013/`에 별도로 기록한다. 실제 TXT·DOCX·XLSX·PDF parser child, 후속 문서·동일 요청·철회·바이트 변경·혼합 첨부 한도·취소 회수를 검사한다. 링크의 실제 취득, 전체 파일/원문 의미 gold, 물리 파일 선택·Retina, 여러 호스트·음성·대표 자원·정식 배포는 이 전달로 완료되지 않는다.

0.3.92의 [아홉 도식](alden-0.3.92/README.md)은 해당 판본으로 보존한다. 이 판본의 Desktop 입력 경로에는 파일 byte store·문서 parser child·문서 참조 digest와 후속 자료 CAS가 추가됐다. 모델 기본값과 로컬 RAM/가용성·명시 자동 모드 정책은 기존 선택을 따른다.
