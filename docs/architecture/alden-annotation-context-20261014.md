# Repeated context with source-specific tag declarations

The installed 0.3.105 reader keeps two identical promotional bodies separate
when their retained topics/entity tags differ. A real selected career query
therefore repeats one body. The new presentation keeps that body once while
retaining every selected original's source ID, version, hash, permission,
author/date and bounded tag declarations. This is context presentation, not
source, identity or factual-relation merging.

## Exact boundaries

`retained-threads-annotation-context-v2` requires the existing exact complete
Threads text, author, handle, date and permission context. Non-tag raw fields
and other metadata still match exactly. Only a literal metadata mirror of the
verified raw tag declaration is excluded from the comparison key. Different
projection annotations remain distinct. Missing versus explicitly empty tags
remain distinct; unsupported and over-budget declarations cannot coalesce.
Explicit source pins, latest/time queries, incomplete bodies, other media or
unknown-field changes retain the previous separation rules.

Each original exposes `retained-declared-tags-v1` with `semantic_status:
unverified`. The common declaration helper preserves the quality preview's
32-item/128-code-point limits. Context additionally limits each field to 900
bytes after the same `<`, `>` and `&` expansion used by the quoted model
payload. Source tags do not become confirmed topics or entities.

The group carries `annotation_differences`, recomputed from every original's
declarations. Typed history verifies these flags, preserves per-source tags
and retains compatibility with stored v1 proofs. Unknown fields are discarded;
the existing 64KiB proof limit rejects oversized combined evidence explicitly
without deleting originals. This field limit does not promise that arbitrary
memberships fit the global history budget.

The shared typed/voice knowledge reference keeps tags and the warning that
their meaning is unverified. If the 8,000-character quoted context budget
removes all available references, it reports `budget_exceeded` with a fenced
failure status and asks for a narrower lookup. It no longer reports this
budget failure as an empty search. Existing source-truncation, cancellation
and original role boundaries remain intact.

## Evidence and limits

The same three real career queries retain every original ID/version/hash,
permission and ranked candidate. The promotional query's repeated bodies
change 1 to 0; the other two remain 0. Both promotional originals' differing
topics/entityTags are retained. An isolated typed-history roundtrip preserves
the complete resulting proof; no operating history or source is written.

The fixed installed 0.3.105 source fails the new body-coalescing regression.
Related candidate tests pass 152 cases, including source comparison, history,
voice, unsupported/escaped tags, legacy proofs and explicit combined-budget
failure. An initial two-test baseline harness incorrectly assumed each test
would contribute only one failure; subtest errors exceeded that count. Its
failed receipt is retained, and the focused single body regression provides
the authoritative before result.

Web GPT-6/xhigh performed a read-only contract review. Its escaped-input budget
counterexample was adopted. Its v1-only consumer observations reflected
intermediate edited code and were reconciled against the current v2 tests.
The child ran no tests or writes; parent source and runtime evidence are
separate. Evidence is in the task's `outputs/annotation-context-20261014/`.

Fewer repeated body characters do not prove lower total prompt tokens, quota,
latency, RAM or battery usage: preserved annotations add provenance. Upstream
tag cause, human semantic/identity/time gold, physical voice and the rest of
the full 18 requirements remain open. Build/install/native/CI and normal
signed/notarized production release remain separate delivery gates.
