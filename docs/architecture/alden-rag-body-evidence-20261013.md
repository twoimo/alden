## 우선순위와 보호 조건

- 기존 BM25/RRF 계산 뒤 안정적인 본문/제목 tier를 적용합니다. 각 tier 안의 기존 순서와 RRF 점수는 유지합니다. BM25 후보 수와 두 backend의 합집합 예산은 기존 한도를 유지합니다.
- 모든 원래 질의 단어 그룹이 같은 본문에 있어야 합니다. 조사 변형은 한 단어의 대안이며, 제목과 본문에 흩어진 단어를 결합하지 않습니다. 단어의 인접성·순서·의미 일치를 증명하지 않습니다.
- 후보 예산이 제목으로 가득 찼어도 적격 본문을 제한 안에 포함합니다. 본문 검사 전에 현재 권한/기간 범위를 적용하고, 현재 버전·원본 blob 해시·본문 결속·membership을 검증합니다. 분류에는 검증된 raw record의 noncontent 선언을 사용합니다. 조작된 캐시나 자료 설명은 우대하지 않습니다.
- 명시적인 `also` ID, lexical weight 0의 dense-only RRF, 영어와 고급 질의의 기존 동작을 유지합니다. 명시적인 최신 요청에서는 기존 발행 시각 선택과 후보 admission이 본문 우선 정책보다 우선합니다.
- 원문 검증은 최대 100건이며 미검증 후보 수를 coverage로 구분합니다. 전체 본문 탐색은 기존 100,000문서/32MiB 텍스트 예산 안에서 수행하므로 탐색 전체를 100건으로 제한한 것은 아닙니다. 각 문서/검증 사이에 취소를 확인하며 단일 문자열·SQLite 호출의 즉각적인 선점까지 증명하지 않습니다.

선택 근거는 `matching_current_version_bound_body`로 표시합니다. 이것은 허용된 현재 버전과 결속된 검색 후보이며 원문 발언의 진실성이나 독립 의미 gold를 뜻하지 않습니다. `source_record; not independently verified` 상태를 유지합니다.
