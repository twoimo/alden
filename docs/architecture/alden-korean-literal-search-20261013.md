# 붙은 한국어 검색과 현재 출처 보존

0.3.87의 저장 본문에는 `이자리35년336`, `두번째올해49년814`가 있었지만
`35년`·`49년`으로 해당 기록을 찾지 못했다. 기본 FTS5는 연속된 문자·숫자를
단어로 처리한다. trigram은 두 글자 검색을 해결하지 못하므로 기존 단어 검색을 유지하고
한국어 리터럴 후보를 별도로 보완했다. [SQLite 공식 FTS5 문서](https://sqlite.org/fts5.html).
실제 고정 Python 3.11 런타임의 SQLite는 3.46.0이다.

## 검색 계약

기존 FTS 단어 일치의 순위가 먼저이고, 새 리터럴 후보는 뒤에 붙인다.
한국어를 포함하는 2~64문자 단어와 단순 AND/OR, 따옴표 리터럴을 지원한다.
한 글자·영문만 있는 단어·65문자 이상·24개 초과·고급 NOT/컬럼/prefix/NEAR는 기존 경로를 따른다.
NFC와 검색용 영문 소문자 처리는 비교에만 적용하고 원문 공백·본문·원본 ID·URL·버전·바이트를 변경하지 않는다.

검색 후보를 먼저 계산한 뒤 허용 프로젝트의 현재 버전을 선택하고, 현재 본문이 실제로 일치하는지 확인한다.
다른 프로젝트의 최신 버전·삭제 문서·denied 자료·과거 버전이 선택되지 않는다.
그래프의 대상·플랫폼·유형·시간·관계 필터와 전체 범위 집계, 페이지 경계를 유지한다.
읽기 작업은 FTS나 원본 테이블을 쓰지 않으며 별도 인덱스·재임베딩·자동 병합을 만들지 않는다.

GraphRAG는 현재 범위에 있는 저장/보존 본문을 같은 기준으로 비교한다. 선택 후에는 기존
원본 SHA·버전·권한 검사와 보존 본문 바이트 대사를 통과해야 한다. 캐시만 위조된 본문은 거절한다.
단어와 리터럴의 차이는 `lexical_match`, `lexical_policy`로 기록하며 Dense가 없을 때
리터럴 후보가 추가된 결과는 `bm25_with_literals`로 표시한다. 이는 의미 진실이나 사람 동일성 판정이 아니다.

## 실제 관찰과 한계

실제 저장 정정 두 문서의 사과/35년/49년/80년 네 질의에서 기대 기록 발견은
primitive top8·그래프·RAG top6 각각 2/4에서 4/4로 바뀌었다. 모델 추론과 원음 확인은 하지 않았다.
기본 RAG top3은 1/4에서 2/4로 바뀌었고, 35년·80년의 기대 정정 기록은 아직 상위3 밖이다.
명시 선택이나 후보 상한을 사람 gold·전역 Recall·모델 답변 품질로 부풀리지 않는다.
기존 단어 순위를 유지하는 규칙과 별도로 독립 평가셋에 근거한 랭킹 개선이 남아 있다.

단순 전체 범위 재탐색 후보는 통합 질의 중앙값 약 648~777ms로 관찰돼 제외했다.
후보 선별 방식은 실제 두 범위·4질의·순차3회에서 약 63~104ms로 관찰됐다.
캐시·동시 로컬 검사·실행 순서가 통제되지 않았으며 p95·인과 성능 향상·전체 앱/FPS/GPU/배터리 결과가 아니다.
기존 단어 검색의 반환 필드와 순위는 별도 수정 전후 해시 대사로 확인한다.

독립 Web GPT-6/xhigh 회귀8개는 구현 전 24개 세부 실패를 재현했고 이후 통과했다.
관련 Python169개·native137개·고정 범위 검사·strict Clippy를 확인했다.
설치·실제 네이티브 질의·CI·보존·로컬 패키지 검증은 별도 전달 단계다.
