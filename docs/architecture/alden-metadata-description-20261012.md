같은 파일명과 공통 설명의 일치를 실제 파일 내용·엔터티 동일성이나 강한 의미 근거로 승격하지 않는다. 원문을 열지 않은 자료를 읽었다고 표시하지 않으며 원래 노드·구조 관계·검색 벡터를 보존한다. 이 변경은 추론 후보의 근거 분류이고 학습·자동 병합·원본 삭제가 아니다.

## 발견과 정책v3

`source-content-evidence-v3`는 기존 비내용 선언·전체 미열람 안내에 더해 확인한 kind와 전체 설명 문자열의 쌍을 `metadata_description`으로 구분한다. code/현재 checkout 소스 파일과 hub/파일 시스템 디렉터리에만 적용한다. 문자열 내부 인용·새 kind·일반 문서 본문을 무조건 배제하지 않는다. 기존 원문 공백·NFC/줄바꿈 규칙·날짜/단위/이름·ID·버전을 보존한다.

개발 감사의 검증 모드는 이미SHA로 대조한 canonical source의 kind/content_indexed 선언을 같은 분류에 넘긴다. source hash/JSON 검증 실패를 내용 후보로 쓰지 않고 지적·unverified 수량을 남긴다. 제품 수동 품질 확인은 원문 blob을 새로 읽지 않고 현재 투영을 검사한다. 개발schema4/제품schema3·정책v3·설명 수량의 분할을 엄격하게 확인하며 예전 결과를 완료0으로 표시하지 않는다.
