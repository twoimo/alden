# 중복 지식의 가역 검토 경로 — 소스 후보

이 문서는 설치된 Alden 0.3.63의 완료 보고가 아니다. 같은 문자열이 서로
다른 사람·문서·출처를 뜻할 수 있으므로, 기존 품질 감사의 후보를 자동으로
병합하지 않고 명시적인 원문 검토 결정을 보존하는 경로를 준비했다.

기억 정리 화면의 접힌 ‘중복 지식 검토’에서 하나의 프로젝트를 선택하고
2–16개 자료와 판단 근거를 지정한다. 미리보기는 현재 허용된 멤버십·버전과
원래 방향 관계를 읽어 SHA-256 계획을 반환한다. 적용은 명시적인 확인을
요구하며, 쓰기 트랜잭션에서 버전·권한·관계·결정 revision을 다시 검사한다.
처음 기능 테이블을 만들기 전에 SQLite 일관 백업을 보존한다.

원본 blob·문서·멤버십·관계·버전·수집 journal을 덮어쓰지 않는다. 별도
기능 테이블에 표시 결정과 append-only 이력을 기록한다. 되돌리기는 활성
표시 묶음만 제거하며 완료 요청 ID의 재실행은 원래 결과를 반환한다.
응답을 놓친 UI는 로컬에 보존한 동일 요청을 조회하고 같은 ID로 재확인한다.

## 표시 범위와 근거

하나의 프로젝트에서 현재 유효한 묶음의 모든 원래 자료가 표시 페이지에
있을 때만 대표 노드로 표시한다. 부분 검색·다른 현재 버전·권한 변경은
원래 노드를 유지한다. 원래 관계 ID·방향·근거와 병합 전 끝점을 보존하며,
묶음 내부 관계도 별도 metadata에 남긴다. 전체 허용 범위의 자료/관계
수량과 현재 표시 노드 수를 구분한다. UI는 이를 사용자 검토 결정으로
표시하며 의미 정답이나 새로운 출처 사실로 승격하지 않는다.

통합 화면은 공유 ID 뒤의 현재 허용된 프로젝트·대상·버전·제목을 함께
보존한다. 모든 표시 맥락이 같은 전체 멤버 집합과 같은 대표 자료를
명시적으로 검토했을 때만 한 노드로 묶는다. 한 프로젝트의 결정만 있거나
다른 대상이 미검토이면 원래 노드와 프로젝트별 검토 정보를 유지한다.
대표 충돌·부분 페이지·현재 버전 변경도 자동 동의로 바꾸지 않는다.

상세 화면은 프로젝트별 결정과 현재 묶음 적용 여부, 표시 버전의 일치
여부를 구분한다. 다른 맥락의 검토가 현재 본문을 검증했다는 뜻은 아니다.
원래 관계 ID·방향·근거·끝점과 내부 관계는 표시 묶음에서도 보존한다.
자료 전체 수량과 이 페이지의 표시 수량도 별도로 유지한다. 의미상
동일성의 독립 정답과 실제 사용자 원문 검증은 여전히 미완료다.

## 확인한 근거와 전달 경계

- 다중 프로젝트 후보의 최종 pinned Python 3.11 -B 검사132개와 UI529개,
  타입 검사·프런트엔드 빌드가 통과했다. 새 독립 읽기 경계 검사11개는
  합성 임시 DB에서 두 프로젝트 동의3→2, 한 결정 undo2→3, 현재 대상·
  버전 차이, 권한 회수/복구, 대표 충돌, 부분 페이지와 제3프로젝트를
  검증한다. 테스트 가정 오류와 반영 전 미실행 범위도 로그에 남긴다.
- 현재 상세 모듈·실제 UI 노트 영역·스타일과 가상 자료를 격리 Chromium
  3크기×2테마/DPR2에서 확인했다. 묶음 적용/원문 유지의12상태·24화면을
  직접 읽었고 가로 넘침/예외0, 각 프로젝트 제목과 마지막 자료 접근 및
  Escape 닫기12/12다. 좁은 창은 노트 스크롤이 필요하다. 실제 앱·물리
  입력·원문 의미 판정의 증거로 확대하지 않는다.
- 합성2,000자료/4,000멤버십의1,984노드 graph_page만 측정했다. 최종
  교대12쌍의 p50은 기존49.628→후보64.983ms, 관측 nearest-rank p95는
  61.931→92.903ms다. 메타데이터 추가 비용이며 속도 향상이 아니다.
  더 느리거나 변동이 컸던 두 쿼리 실험을 제외하고 기존 후보의 단순
  배치 조회를 유지했다. 전체 read_action/앱 UI/GPU/배터리는 미측정이다.
- 앞선 단일 프로젝트 후보의 pinned Python 3.11 -B 검증113개 전부 통과.
  실제 앱 읽기 경계의 추가3개를 포함한 projection7개를 포함한다.
- 격리된 앱 읽기 경계: 3개 자료 → 2개 표시 묶음 → 되돌리기 후 원래
  페이지와 정확히 일치. 관계 ID·방향·근거 유지, 본문 변경/부분 검색과
  여러 프로젝트 보기에서는 자동 통합하지 않음.
- 최초 소스 후보의 UI488개, 타입 검사, Rust121개와 strict Clippy 통과.
  happy-dom 검사는 실제 픽셀·물리 입력·설치 동작을 대신하지 않는다.
- 복구된 요청 결과의 그래프 갱신 알림 누락과 거절 사유 누락을 새 회귀로
  재현했다(2실패/기존6통과). 두 경로를 수정해 관련8개/전체UI490개와
  타입 검사를 포함한 프런트엔드 빌드가 통과했다. 성공한 결정만 갱신을
  알리고 동일한 요청을 다시 적용하지 않으며 실패 사유를 보존한다.
- 실제 모듈·스타일을 사용한 격리 Chromium 화면에서 고정 가상 자료로
  720×620, 1200×800, 1800×1000 / light·dark / DPR2를 검증했다.
  비교·확인 영역12캡처를 직접 읽었고 가로 잘림/예외0, 확인 영역 접근 및
  키보드 확인 전환6/6이다. 실제 Retina 기기·앱 연결·원문 의미 판정은
  포함하지 않는다. 최초 styles.css를 빠뜨린 준비 캡처는 비교에서 제외했다.
- 완전한 스타일 기준본의 버튼 최소 높이30.796875px→36.59375px는
  동일한 가상 화면의 기하 관측이다. 앱 속도·사용성 개선율로 확대하지 않는다.
- 설치본은0.3.63이며 이 후보는 아직 canonical build, 설치, native
  화면 검증, 원격 CI와 운영 병합으로 전달하지 않았다.

독립 검토자는 후보5묶음/14메타데이터 레코드만 확인했다. 개별 원본·출처
읽기2건은 OpenAI가 요청의 보안 상태를 판단하지 못해 차단했다. canonical
blob·원본 ID·작성자/URL·개정 및 방향의 새 독립 검증은 미완료다.

작업자의 원본 식별자 검증·수집 이벤트 지문·활성 묶음 수 제한·백업 시간
제한을 더하는 후속 소스 수정도 같은 보안 상태 판정에서 차단됐다.
현재 두 파일을 읽어 보강이 반영되지 않은 상태를 확인했다. 해당 수정을
다른 실행기나 위임으로 재시도하지 않았으며 설치·운영 사용은 보류한다.

증거는 작업 루트의 outputs/entity-union-20261011/, 기존
outputs/entity-resolution-20261011/ 및
outputs/entity-evidence-review-20261011/에 남긴다. 18개 전체 목표와
원래 후속 요청의 완료 조건을 유지한다.
