## 3. 에너지·힘·방향·코사인·사실 관계의 구분

위치 `x_i`의 에너지 `E`는 스칼라이고 힘은 `F_i=-∂E/∂x_i`라는 벡터다. 예를 들어 `E(x,y)=0.5*(x²+4y²)`에서 `(2,0)`과 `(0,1)`의 에너지는 모두 2지만 힘은 `(-2,0)`과 `(0,-4)`다. 같은 에너지가 같은 힘·방향을 뜻하지 않는다. 방향만 같아도 크기가 다를 수 있다. 서로 다른 위치에서 같은 힘을 받거나 총힘이 상쇄돼 0이 되어도 콘텐츠 유사도나 사실 관계는 도출되지 않는다.

현재 링크 스프링은 `δ=x_j-x_i`, `r=||δ||`, `F_i=k*(r-l)*δ/r`, `F_j=-F_i`이다. 방향은 **현재 화면에서 상대 노드가 있는 방향**이다. 고용·인용·반박 같은 사실 관계의 source→target 방향이나 임베딩 좌표축의 방향을 뜻하지 않는다. 반대 방향의 두 사실 관계가 같은 근접성을 만들 수 있고, 그 관계들은 상세와 원본 그래프에서 별도로 남아야 한다.

같은 프로필의 유효한 임베딩에 대해서만 `s_ij=(z_i·z_j)/(||z_i||||z_j||)`를 정의한다. unit normalization이 확인됐다면 내적이 코사인이다. 값이 높다는 것은 해당 인코더·입력 표현에서 가까운 콘텐츠라는 뜻이며, 같은 사람·같은 문서·참인 주장·지지 관계라는 뜻이 아니다. `(1,2)`와 `(2,4)`는 코사인 1이어도 다른 벡터·다른 엔터티일 수 있다. 영벡터, NaN/Infinity, 서로 다른 차원·encoder·pooling·역할의 입력은 affinity를 계산하지 않는다. 임베딩의 음수 코사인을 곧바로 논리적 반박이나 사실 반대 방향으로 바꾸지 않는다.

현행 작은 앵커에 있는 `affinity=.3/.06` 변수는 **초기 위치로 돌아가는 계수**다. 이름이 affinity여도 의미 벡터 유사도 항이 아니다. 현행 `.08` navigation 가중치 역시 위치 유도를 위한 정해진 값이며 근거 신뢰 확률이 아니다.

고정 앵커·고정 링크 동안의 이상적 물리 항은 다음 에너지로 설명할 수 있다.

```text
E_anchor = (18/2) Σ_i ||x_i-a_i||²
E_link   = (1/2) Σ_(i,j) k_ij (||x_i-x_j||-l_ij)²
E_rep    = Σ_(i,j in same component) .045/sqrt(r_ij²+.0324)
E_contact= (36/2) Σ_(i,j in same component) max(0,.18-r_ij)²
k_ij     = 14*(.25+.75*strength_ij)/sqrt(max(1,degree_i*degree_j))
```

이 식은 코드의 힘을 항별로 설명하는 도출이며, 이산 계산 전체에서 에너지가 단조롭게 감소한다는 증명은 아니다. 힘의 상한 처리, 타원체 경계로의 사영, 같은 위치에서 인덱스에 따라 정한 미세 분리, 앵커 변경, 용량 제한으로 잘린 링크, 시간 간격의 상한이 추가된다. 감쇠 `exp(-11h)`는 속도를 줄이는 연산이며 의미 정보를 더하지 않는다. `advance`는 최대 8개 세부 단계와 최대 .25초의 경과 시간을 처리하므로, 긴 프레임을 항상 1/120초 간격으로 계산한다는 계약도 아니다.

**수치 잔차, 화면의 정지, 정지 플래그는 별도로 평가한다.** 현행 `maxForce`는 경계에서 바깥쪽 법선 성분을 제거한 힘을 사용할 수 있으므로 전체 원래 힘을 뜻하지 않는다. 부모의 visual-rest 수정은 화면 배율을 사용해 작은 좌표 이동, 잔차, 속도를 판정한다. 경계의 제약을 받으면 원래 힘이 0이 아니어도 화면은 멈출 수 있다. `settle()`는 최대 960단계 뒤 속도를 0으로 만들고 moving을 false로 설정하므로, 이 플래그만으로 자연스러운 평형에 도달했다고 판정하면 안 된다. 어느 정지 판정도 내용이 올바른 의미 군집으로 나뉘었다는 증거가 아니다.

이 절은 수식의 직접 도출과 소스 관찰에 근거한다. 신경과학이나 표현 학습의 새로운 학술적 효과를 주장하지 않으며, 논문의 기여를 빌려 미검증 설계 효과를 정당화하지 않는다.

허브 편향의 정적 근거도 있다. 작은 뷰의 앵커 링크는 `selectSynapses`가 강도순으로 최대 144/512개를 선택하며, 연결 성분도 이 부분 집합으로만 구성한다. 강한 허브 링크가 선택 예산을 차지하면 약한 군집 내부 링크가 빠질 수 있다. `relationCenterId`는 강도의 합과 중요도로 중심을 고른다. Plasticity의 degree 정규화는 가속도와 과도한 수축을 줄이지만, 선택에서 빠진 링크를 복구하거나 의미 벡터에서 과도하게 이웃으로 선택되는 허브 문제를 해결하지는 않는다. 큰 overview에서 출처를 번갈아 선택하는 방식은 표시 출처의 편향을 줄이는 조치이며 의미 품질 평가는 별도로 필요하다.

동일한 정형 문구를 가진 다른 사람과 기업은 기존의 안정 ID를 유지한다. 현재 코드는 텍스트로 잘못된 자동 동일시를 수행하지 않지만 의미에 따른 근접성도 계산하지 않는다. 제안한 affinity로 같은 문구의 서로 다른 엔터티가 가까워지더라도 노드, 출처, 관계를 합치지 않고, 축약 표시에서도 원래 항목 수와 상세 내용을 보존해야 한다.

## 5. 최소 데이터 계약 — 부모 담당자에게 제안

기존 graph page, 벡터 저장소, UI 상태 관리를 재사용한다. 별도의 LLM, 상주 서비스, 프로필 변경은 추가하지 않는다. 아래 내용은 부모가 구현하고 검증할 계약 제안이며 현재 구현된 기능이 아니다.

### 5.1 그래프 스냅샷과 결합

graph page와 같은 권한 범위에서 반환된 노드 집합만 affinity 후보의 입력으로 사용한다. 각 노드의 키에는 표시 ID와 원본 ID의 명시적 대응, 선택된 `source_target`, `source_version`, 기존 인덱스 생성 경로의 `text_hash`를 포함한다. `memory:` 접두사는 기존의 명시적 원본 ID 대응으로만 해소한다. 이름, label, space가 같다는 이유로 엔터티를 결합하지 않는다.

스냅샷 키에는 현재 사용자·계정 식별, 프로젝트·대상·검색·시간·종류 필터, 읽어 확인한 권한·소속의 요약 해시, graph revision, 선택된 ID·버전·대상 집합의 요약 해시를 포함한다. 기존 이벤트 revision이 권한 변경까지 반영한다고 가정하지 않는다. 권한 요약 해시는 정본 조회에서 새로 결합해야 하는 정보이며, 기존 서버가 이미 permission epoch를 제공한다고 표현하면 안 된다.

그래프와 벡터가 별도 DB에 있으므로 그래프 스냅샷 → 저장 벡터 조회 → 현재 소속·버전·권한 재확인 순서로 정합성을 검사한다. 현재 버전이나 text hash가 바뀌면 후보를 폐기한다. 여러 DB를 아우르는 일괄 트랜잭션이 구현됐다고 가정하지 않고, 낙관적 검증 중의 변경과 충돌을 검출하는지 테스트한다. 화면 적용 시에도 UI epoch와 스냅샷 키를 확인한다. 권한 범위 변경이나 권한 만료 통지를 받으면 기존 도형과 후보를 무효화한다. 조회 실패를 빈 자료나 삭제로 바꾸지 않고 실패 상태와 미적용 건수를 구분한다.

### 5.2 기존 프로필을 지키는 벡터 재사용

collection에서는 기존 `(document_id,version,text_hash,model,endpoint,encoding)`이 현재 출처와 일치하는 행만 읽기 전용으로 얻는다. BLOB 길이로 차원을 확정하고 모든 원소가 유한한지, 벡터 길이가 양수인지, 단위 길이 정규화가 유효한지 확인한다. model에 revision이 포함돼 있는지 또는 저장된 인덱스 생성 정보로 revision을 확인할 수 있는지도 검사한다. endpoint가 같거나 차원이 같다는 것만으로 프로필 호환성이 성립하지 않는다.

호환 키에는 최소한 인코더 ID와 revision, 차원, tokenizer 및 입력 변환 버전, passage/query 역할, window/stride/pooling, normalization, 인덱스 및 텍스트 투영 버전을 포함한다. 기존 `ENCODING='e5-char256-stride192-weighted-unit-pool-v1'`와 `TEXT_VERSION='retained-local-original-text-v1'`을 유지한다. 기존 메타데이터로 필요한 정보를 확인할 수 없는 행은 프로필 미확인으로 표시하고 R만 사용한다. 새 프로필을 만들거나 임의로 재임베딩하지 않는다.

memory dense index에서는 model/endpoint/index_version/watermark/dim을 확인한다. collection과의 텍스트 표현, pooling, 입력 역할 호환성이 불명확하면 동일한 384차원이어도 함께 비교하지 않는다. 기존 공통 프로필을 확인한 부분만 같은 affinity 집합에 포함한다. 대응되지 않는 엔터티·문서, 오래된 watermark, 영벡터, 준비되지 않은 원문, 비호환 프로필은 사용 가능한 벡터의 부족으로 기록한다. 출처별 배치로 이를 채우고 의미 군집이라고 보고하지 않는다.

UI overview는 본문을 받지 않으므로 UI에서 label만 임베딩하거나 body hash를 추정하지 않는다. 부모의 백엔드 어댑터가 저장 인덱스를 조회한다. 레이아웃에서 `retrieve()`나 `_active_dense_embedding_model()`의 검색·프로브 경로를 호출해 새로운 query embedding, 모델 선택, 모델 로딩을 일으키지 않는다. 이미 준비된 인덱스 생성 정보로 확인할 수 없는 벡터는 미검증으로 제외한다.

### 5.3 사실 관계와 분리한 affinity 출력

```text
AffinitySnapshot (additive proposal)
  schema, inputSnapshotKey, requestGeneration, profileKey, affinityRevision
  coverage: permittedVisibleNodes, compatibleCurrentVectors, usablePairs,
            staleOrUnknownProfileCount, candidateTruncation
  pairs[]:
    a: {displayId, canonicalId, sourceTarget, sourceVersion, textHash}
    b: {displayId, canonicalId, sourceTarget, sourceVersion, textHash}
    cosine, layoutWeight, methodVersion
```

건수도 권한 안의 표시 집합에서만 계산한다. 숨겨진 ID, 항목 수, 중심 위치, 의미 라벨을 클라이언트에 노출하지 않는다. 부모의 타입, parser, sanitizer는 이 계약을 별도 경로로 처리한다. `KnowledgeGraph.edges`, `relations`, OSK의 사실 관계, 검색 근거 트리플에는 쓰지 않는다. 기존 `purpose='semantic'` edge에 affinity pair를 섞지 않는다.

기존 graph/signature에 더해 affinityRevision, profile, 스냅샷 키의 변경도 레이아웃 입력 signature에 포함한다. 오래된 응답이 새로운 도형, 선택, 카메라, 핀을 덮어쓰지 못하도록 현재 `CollectionGraphController`의 epoch 검사를 확장한다. 기존 SourceVersion/SourceTarget을 확인하는 활동 점등은 유지한다. affinity 계산을 실제 사고나 독서 활동으로 점등하지 않는다.

## 6. 실제 관계와 affinity로 큰 뷰를 군집화하는 절차

### 6.1 후보와 가중치

1. **R**은 현재 허용된 스냅샷의 유효하고 명시적인 관계만 사용한다. 방향, type, evidence ID를 보존하면서 레이아웃 계산에 사용할 대칭 형태를 별도로 만든다. navigation의 군집 가중치는 0으로 한다. 양의 `w/(1+w)`를 사용하고 같은 쌍의 중복 출처를 더해 강도를 부풀리지 않는다. weight 0인 관계를 사실 표시에서 지울 필요는 없지만, 힘 0이라는 계약을 채택한다면 물리와 군집 연결에 대한 기여도 0이어야 한다.
2. **S**는 같은 호환 프로필의 현재 벡터에서 후보를 얻고 정확한 코사인 값으로 다시 순위를 매긴다. 초기 제안은 노드마다 k=4인 상호 최근접 이웃만 사용하는 것으로, 최대 4096개의 무방향 쌍이다. `tau_on`은 실제 정답 라벨 평가로 결정한다. 초기 시험값 .80과 이탈용 `tau_off=.75`는 교정 전 가설이며 E5에서 검증된 적정값이 아니다. 오래된 버전이나 권한 만료에는 이탈 지연을 적용하지 않고 즉시 제거한다.
3. 같은 text hash를 가진 정형 문구 집합의 ID는 유지하고 집합 내부 쌍은 의미 평가에서 별도로 분류한다. 동일 입력 수 `q`에 따른 `1/sqrt(q_i*q_j)` 등의 가중치 감소와 hash별 기여 상한을 둔다. 모호한 이름이나 정형 문구만으로 얻은 높은 코사인 값을 엔터티 동일성 판정에 쓰지 않는다. hash가 다른 바꿔 쓴 문장도 있으므로 hash 검사만으로 잘못된 근접성 문제가 해결됐다고 하지 않는다.
4. R과 S를 각각의 가중 degree로 `w_ij/sqrt(max(epsilon,d_i*d_j))`에 따라 정규화하고 노드별 총 기여에 상한을 둔다. `W=R_normalized+alpha*S_normalized`, 초기 `alpha<=.25`를 시험한다. S만 있는 노드도 처리하지만 약한 S가 근거가 있는 R을 지우지 않는다. `alpha`는 힘이나 사실의 신뢰 확률이 아니다. 허브 정규화 전후와 S-only 결과를 별도로 평가한다.

기존 LSH를 재사용할 수 있는 프로필은 후보 탐색 가속에 활용한다. 다만 현재 collection 검색은 전체 후보를 채점하므로 collection에 ANN이 이미 있다고 말할 수는 없다. 최소 추가안은 저장된 단위 벡터로 메모리 안에 구성하는 프로필별 결정적 후보 인덱스다. 원본 DB나 프로필은 바꾸지 않는다. 노드별 최대 64개 후보를 정확한 코사인으로 재평가하는 방안을 검증한다. 같은 bucket에 자료가 몰리면 hash별 대표와 기존 R 이웃을 우선해 동일 문구 복제본이 후보 예산을 독점하지 않게 한다. 후보 잘림과 정확한 kNN에 대한 재현율을 기록하고 탐색 가속만으로 품질을 추정하지 않는다.

2048개 노드의 전체 쌍은 2,096,128개이며, 384차원이면 약 805 million multiply-add 항이 필요하다. 이는 산술적 작업량이며 실측 지연이 아니다. 매 프레임 계산하지 않는다. 처음에는 백그라운드 worker에서 스냅샷 단위로 계산하고 이후에는 변경 ID와 기존·새로운 인접 후보만 갱신한다. 후보 64개 상한은 퇴화한 경우의 숨은 전체 쌍 비교를 제한하는 예산이다. 품질이 나빠지면 계산 종료를 품질 합격으로 처리하지 않는다.

### 6.2 출처 이름에 의존하지 않는 군집과 앵커

R+S의 W에 대해 결정적이고 횟수가 제한된 커뮤니티 갱신을 수행한다. 첫 실행은 안정 ID순으로 국소 이동하고 재실행은 이전 커뮤니티 라벨에서 시작한다. 제안은 가중 modularity가 개선되는 이동만 허용하는 최대 8회 순회, 고정 동점 규칙, 변경 주변만 활성화하는 방식이다. degree와 해상도 계수를 기록한다. 연결 성분 전체를 하나의 군집으로 삼으면 허브로 인해 거대 군집이 생기므로 채택하지 않는다. 제한된 순회 뒤 멈췄다고 최적해라고 표현하지 않는다.

커뮤니티 라벨에 원본 출처 이름을 사용하지 않는다. 이전 군집과의 구성원 겹침으로 군집을 대응시켜 기존 군집의 ID, 중심, 방향을 유지한다. 새 군집은 안정적인 구성원 ID로 초기 중심을 결정한다. 무관한 군집 수가 바뀌어도 모든 중심의 배율을 바꾸지 않는다. source/space는 필터, 분류, 출처 정보로 유지하고 의미 라벨과 구분한다. 새 의미 영역을 추가할 때도 기존 출처 영역의 이름만 바꾸지 않는다.

국소 목표 위치의 에너지 제안은 다음과 같다.

```text
E = 1/2 Σ_(R pairs) kR_ij (r_ij-lR_ij)^2
  + 1/2 Σ_(S pairs) kS_ij (r_ij-lS_ij)^2
  + 1/2 Σ_i mu_i ||x_i-x_i_previous||^2
  + 1/2 Σ_i beta_i ||x_i-c_cluster(i)||^2
  + E_spatial_collision + E_bounded_volume

F_ij = k_ij*(r_ij-l_ij)*(x_j-x_i)/r_ij, F_ji=-F_ij
```

R의 rest length는 현행식을 초기 후보로 사용하고, S는 코사인 값을 상한·하한이 있는 가중치와 rest length로 변환한다. 예시는 `a=max(0,(s-tau)/(1-tau))`, `kS=alpha*normalized(a)`, `lS=.9-.25*a`다. 모두 표시 좌표 단위이며 의미 거리의 충실한 척도는 아니다. r이 0이면 ID 쌍으로 결정한 미세 방향을 사용한다. 0weight에도 최소 스프링 계수를 더하는 현행식을 S에 그대로 적용하지 않는다. 실제 노드 반경보다 짧은 rest length를 피한다.

군집 중심으로의 인력은 군집 분리를 돕는 약한 항으로 사용하고, 지나치게 크게 설정해 항목을 한 점으로 압축하지 않는다. 새 노드는 유효한 R/S 이웃의 이전 위치를 가중 평균하고 결정적 미세 오프셋을 더한 위치에서 시작한다. 고립 노드는 ID로 정한 빈 위치에 배치하며 출처 그룹에 넣지 않는다. 명시적인 contradicts 관계나 같은 어휘를 쓰는 주장은 같은 논점으로 가까이 놓일 수 있지만, 서로 다른 주장과 유효 시간, 관계 유형이 구분되는 표시는 유지한다.

충돌은 같은 연결 성분 안으로 제한하지 않고 표시 집합 전체의 근접 grid로 검사한다. 일반적인 계산 예산은 `O(V+|R|+|S|+nearPairs)`지만 모든 점이 한 셀에 모이면 최악에는 전체 쌍을 검사하게 된다. 셀 점유 수를 관측하고 결정적 분할이나 국소 재배치를 수행하며, 해결하지 못하면 과밀 상태를 보고한다. 계산을 중단한 결과를 충돌 0으로 보고하지 않는다. 군집 수가 64개를 넘으면 출처 기준의 가짜 군집으로 묶지 않고, 상위 계산에도 grid·계층화를 적용하거나 예산 내 미완료로 표시한다.

## 7. 120개 물리 계산과 2048개 표시에 맞는 통합

**2048개를 표시하면서 전체 2048개를 매 프레임 물리 계산할 필요는 없다.** 작은 `PlasticityLayout`을 2048개로 확장하는 방안은 이 최소 설계에 포함하지 않는다.

- 첫 실행이나 사용자가 요청한 전체 재배치에서는 worker가 R+S로 전체 표시 노드의 앵커를 계산한다. 메인 스레드는 현재 스냅샷과의 일치를 확인한 결과를 한 번 받아 표시 위치에 반영한다. 큰 계산은 이벤트·스냅샷 단위이며 상시 프레임 물리가 아니다.
- 일반 갱신은 변경 ID와 이전·새로운 R/S 이웃으로 활성 집합을 만든다. 최대 120개 예산에는 고정 경계 노드도 포함하고 나머지 위치는 고정한다. 현재 배열의 앞 120개를 그대로 선택하면 뒤쪽 ID에 발생한 변경을 처리하지 못한다. 부모가 변경 집합에서 물리 계산용 뷰를 만드는 어댑터를 추가해야 한다.
- 새 앵커를 계산하기만 해서는 활성 뷰 밖의 기존 위치가 갱신되지 않는 문제를 수정한다. 처음 큰 재배치를 하거나 변경 집합이 예산을 넘으면 worker가 변경 ID를 명시한다. 물리 뷰 안은 제한된 물리 계산을 사용하고, 밖은 같은 스냅샷의 목표까지 유한 시간 보간을 적용하거나 reduced motion일 때 한 번에 적용한다. 두 경로의 완료를 별도로 기록한다.
- 표시 보간을 추가한다면 `pointsTweenMoving`을 기존 루프의 interactive/stop 판정에 포함한다. 보간이 끝난 뒤 정확히 정지하고 물리의 moving=false만으로 미반영 점을 남기지 않는다. 기존 표시 위치, 선택, picking 동기화를 재사용하며 보이지 않는 점의 상시 갱신을 추가하지 않는다.
- 국소 변경이 120개를 넘으면 영향 영역을 안정 ID순의 제한된 배치로 처리하거나 명시적 전체 재배치로 보낸다. 미처리 항목이 있으면 건수를 표시한다. 이전 버전의 S를 계속 쓰지 않으며 만료된 쌍은 먼저 제거한다. 대량 변경에서도 전혀 움직이지 않는 배치와 최고의 품질을 동시에 보장한다고 하지 않는다.
- 작은 뷰도 같은 의미 목표와 위치 캐시를 사용해 120/121개 전환에서 다른 시드 방식으로 돌아가지 않게 한다. 국소 상세 뷰는 실제 링크의 물리 계산을 추가할 수 있지만 overview의 공간 기억을 자동으로 초기화하지 않는다.
- 관계 도형과 사실 상세는 원래 direction/type/evidence를 사용한다. S는 기본적으로 위치 계산에만 사용한다. S를 선으로 표시한다면 별도의 범례와 외형으로 유사도에 따른 배치임을 명시하고 사실 edge 수나 실제 활동 경로에 포함하지 않는다.

자연스러운 물리 정지, 표시 보간 정지, worker 완료, 군집 품질 합격을 네 상태로 구분한다. 표시 정지만으로 의미 군집 완료를 선언하지 않는다. pause나 reduced motion으로 강제 정지했다면 그 이유도 별도로 기록한다.

## 8. 위치·핀·카메라·선택·권한·버전의 유지 조건

철회는 출처와 사실 상태를 기준으로 판단한다. 코사인이 임계값보다 작아졌다는 것은 사실의 철회를 뜻하지 않는다. 근접성이나 사용 횟수에 따라 사실의 가중치와 신뢰도를 변경하지 않는다.

재연결에서는 현행 `CollectionActivity`의 stream ID/cursor/reset/epoch 계약을 유지한다. 같은 스냅샷의 재수신은 no-op이며 다른 스냅샷은 버전이 있는 차이로 적용한다. 누락이나 reset이 발생하면 일관된 graph snapshot과 여기에 결합한 affinity를 다시 얻고 권한 안에서 가능한 위치를 보존한다. 과거 활동을 재생해 현재 활동처럼 점등하지 않는다. 미구현 서버 push나 영속 layout queue가 있다고 가정하지 않는다.

## 9. full2048의 CPU·정착·품질 기준

### 9.1 이번에 측정한 범위

Node `v26.10.0`에서 현행 함수를 실행했다. 합성 노드 2048개와 합성 방향 관계 4096개를 사용했다. 준비 실행 30회와 측정 100회의 overview 앵커 시간은 p50 약 .4895ms, p95 약 .6803ms, 최대 .9188ms였다. 이는 **관계를 쓰지 않는 시드 배치식의 pure JS 시간**이다. 실제 데이터 조회, 벡터 검증, S 후보 생성, 군집 계산, GPU 렌더, 입력 지연은 포함하지 않는다.

같은 합성 뷰에서 실제 계산된 120개 노드와 237개 시냅스는 60fps에 해당하는 `advance` 430프레임, 시뮬레이션 시간 약 7.1667초에서 자연 정지했다. CPU user 139.097ms, system 9.291ms, wall 약 156.272ms로 빠르게 계산한 결과이며 실제 앱을 7초 관측한 CPU 값은 아니다. 최종 maxSpeed는 약 .0014401, maxForce는 약 .0191524였다. 표본은 1개 장면의 1회 실행이다. 이를 실제 full2048의 정착 시간, 성능 개선율, 부모 visual-rest 수정의 설치 앱 효과로 보고하지 않는다.

### 9.2 부모 구현의 수용 조건 제안 — 아직 검증하지 않은 예산

실제 허용된 스냅샷에서 collection 1984개와 memory 64개가 모두 표시될 때 full2048로 기록하고, 부족하면 실제 표시 수를 보고한다. 전체 데이터셋의 노드·edge 수, 페이지 표시 수와 반환된 실제 edge 수, affinity 적용 범위, 활성 물리 노드 수를 각각 저장한다. 페이지 밖 문서나 생략된 edge를 포함한 전체 그래프의 의미 품질을 이 페이지 평가로 대신하지 않는다.

| S 후보 품질 | 같은 프로필의 정확한 코사인 top-k 대비 candidate recall@4≥.95를 초기 목표로 둔다. | 허용된 현재 벡터의 고정 평가 부분 집합에서 정확한 결과와 비교한다. LSH 후보 잘림과 동일 문구에서의 퇴화를 확인한다. |
| 실제 의미 품질 | 출처가 달라도 같은 논점인 자료, 같은 출처의 무관한 자료, 같은 문구의 다른 엔터티, 허브, contradicts·개정을 포함한 독립 라벨 집합으로 평가한다. | 출처 소속을 정답 라벨로 쓰지 않는다. precision@10, 군집 쌍별 precision/recall, cluster purity, 적용 범위를 R-only, S-only, R+S, 기존 출처 시드 배치 사이에서 비교한다. |

의미 품질의 초기 가설은 사람이 근거를 확인한 이웃의 precision@10≥.80과 pairwise cluster precision≥.90이며 교정 전 제안값이다. 최종 합격은 **R-only보다 출처를 넘는 같은 논점의 회수가 개선되고, 같은 출처의 무관한 자료·동일 문구의 다른 엔터티·허브의 잘못된 근접률이 증가하지 않는 것**을 짝지은 평가에서 확인하는 것이다. 정답 라벨이 부족하거나 차이의 신뢰 구간이 판단하기에 부족하면 미검증으로 남긴다. 코사인으로 만든 S 자체를 정답으로 삼아 precision을 평가하지 않는다. modularity, silhouette, 뭉쳐 보이는 화면만으로 합격을 판정하지 않는다.

실제 링크의 도형 품질은 정규화 stress, 실제 관계 이웃의 순위, 관계 type별 거리로 기록한다. 모순이나 다른 역할의 실제 관계도 가까이 놓일 수 있으므로 모든 linked pair가 모든 unlinked pair보다 가까워야 한다는 정답을 만들지 않는다. 원래 방향, type, 근거가 보존된 건수와 API 재조회 결과를 별도로 평가한다.

벤치마크는 같은 하드웨어, 전원, 모델, 데이터, 권한, 필터, 카메라, viewport, 동시성에서 수행한다. A/A, 기존 R·시드 배치, 후보의 실행 순서를 교대로 짝짓는다. 준비 전후, 최초·증분·철회·재연결을 나누고 CPU user+system, wall, RSS·버퍼, p50/p95, 관측 시간, 표본 수, 산정 가능하면 95%CI를 기록한다. 소스 SHA에는 부모의 미커밋 변경도 반영한다. 이번 단일 합성 결과로 감소율을 만들지 않는다.

필수 실패 사례에는 120→121개 전환, 뒤쪽 ID의 변경, 노드 1개 추가에 따른 군집 수 변경, 허브 중심 별 모양, 전체 동일 문구, 동명 별개 엔터티, 같은 차원의 다른 프로필, 영벡터, weight 0, 전부 고립되거나 완전히 겹친 노드, source v1/v2 순서 역전, 권한 변경에도 event revision이 바뀌지 않는 경우, 범위 A의 늦은 응답이 B에 도착하는 경우, 인덱스 지연, 중복 이벤트, cursor reset, 비표시 중 변경, 재연결, 선택·핀·카메라 조작 중 갱신을 포함한다.

## 10. 부모의 최소 통합 단위와 되돌림 절차

1. graph page와 벡터 어댑터에서 현재 버전, 권한 요약 해시, 출처에 결합한 키를 대조하고 저장 벡터로만 S를 만든다. 프로필 불일치, 권한 만료, 응답 역전 계약을 먼저 검증한다.
2. parser/signature/epoch에 별도의 affinity snapshot을 연결한다. 사실 edge와 S를 섞지 않고 입력이 같으면 no-op으로 처리한다.
3. 2048개의 이벤트 기반 앵커 계산과 변경 집합 최대 120개의 물리 어댑터를 연결한다. 출처 시드 배치의 이름 변경으로 끝내지 않고 R/S가 바뀌면 목표 배치가 달라지는지, 뒤쪽 ID에도 변경이 적용되는지 확인한다.
4. UI 위치, 핀, 선택, 카메라, 루프 정지를 검증하고 실제 full2048의 품질, CPU, 정착을 측정한다. 부모의 visual-rest 수정과는 별도의 검증 단계로 둔다.

변경을 되돌릴 때는 S 생성과 적용만 제거하고 현재 R과 기존 위치 캐시로 복귀한다. 모델, 프로필, 출처 관계, 원문, 수집 큐는 바꾸지 않는다. 출처나 권한이 만료된 좌표 캐시는 복원하지 않는다. 저장 대상은 방법·버전·입력 스냅샷 키와 임시 레이아웃 캐시이며 S를 사실로 영속화할 필요가 없다.

이 검토의 전달 범위는 소스 근거, 현행 함수의 반례 8개, 구현 가능한 결합 계약과 평가 계획이다. R+S 구현, 실제 데이터의 의미 품질, 설치 앱 표시, 운영 배포는 이 검토자가 검증하지 않았다. 부모의 통합과 후속 검증이 남아 있다.
