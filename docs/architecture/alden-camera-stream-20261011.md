# Alden 0.3.63 — 복원 카메라와 스트림 이벤트 경계

0.3.62 설치본의 작은 창에서 물리 정착 뒤2초 동안60프레임이 추가됐다. 기본 창은 추가 렌더0이었다. 이것만으로 원인이 확정되지는 않지만, 저장 카메라 복원 경로에서 도달할 수 없는 목표를 실제 Three.js controls와 렌더 루프로 재현했다. 복원 거리33.7898에 확대 한계23.7898이 적용돼300프레임 이후에도 루프가 계속 돌았다.

## 라우팅 응답의 실제 HTTP 경계

요청한 GPT-6 Web의 최고 지원강도 chatgpt-web/gpt-6-sol/xhigh 병렬 작업에서, 정상 응답을 여러 data필드로 나눌 때 기존 코드가 각 줄을 JSON으로 읽어 실패하는 결함을 재현했다. 부모도 실제 localhost chunked HTTP 및 새로운 SSE 경계 회귀를 수정 전21건 중2실패/3오류로 확인했다. 외부 제공자·모델·카카오 입력/전송을 호출하지 않았다.

LF/CRLF 스트림에서 data필드를 줄바꿈으로 결합하고 실제 빈 줄에서 이벤트를 처리한다. BOM과 주석은 처리하고, 공백만 있는 미지 필드를 빈 줄로 취급하지 않는다. 응답·한 줄의 크기 예산과 취소/모델/완료 검증은 유지한다. 끝나지 않은 마지막 이벤트는 버리므로 완료 payload를 중간에 수신했다는 이유로 성공을 기록하지 않는다. [WHATWG의 이벤트 해석 계약](https://html.spec.whatwg.org/multipage/server-sent-events.html#event-stream-interpretation)을 확인했다. 이 수정은 LF/CRLF 라우터 스트림의 검증이며, 별도 CR-only producer의 실시간 전달까지 검증한 것은 아니다.

최종 관련Python95개가 통과했다. 실제 소켓의2경우는 고정 라우터 연결을 테스트 프로세스에서만 임시 loopback 포트로 연결하며 이미지 원문/MIME/hash·동일 파일 근거·선택 모델/high·후속 문장을 대사한다. 단위 fixture와 실제 소켓을 구분하며, 설치 Resources의 실행과 사용자 첨부/동시 턴/모델 이미지 이해 품질은 별도 전달/실사용 단계다. Rust119개와 strictClippy도 통과했다.
