# 정본 상세와 원문 관측 검토

노드 상세는 조정된 정본의 SHA가 importer의 written_hash와 일치하면 오래된 source description/facts를 다시 사용했습니다. 그 결과 그래프의 정본 요약과 클릭한 상세가 다른 설명을 보여줄 수 있었습니다. 0.3.27은 정본 summary를 항상 읽고, 수집 캐시의 key_facts로 정본 본문을 덮지 않습니다. 방을 지정한 원문 조회의 구분과 본문 제외 경계는 유지하며 시스템 알림만 있는 결과를 발화 확인으로 설명하지 않습니다.

SDK의 다음 검토 세 구간을 실제로 읽었습니다. 두 inactive 방 관측에는 과거 수량과 기간, 원본 제목이 검증됐다는 자동 문구가 있었습니다. 참조 metadata의 제목은 비어 있었고 현재 게시 corpus에는 해당 방 행이 없었습니다. 메시지 근거는 앞서 확인한 8건씩의 시스템 feed였습니다. 이 본문들은 현재 source checkpoint로 재생성한 legacy 자동 본문과 정확히 일치했고, 마지막 기록 SHA와도 같았습니다.

원래 바이트를 비공개 `_archive`의 opaque `.bin`으로 복사·SHA 확인한 뒤 실제 SDK CAS로 관측의 한계를 명시했습니다. 제목이나 새로운 주제를 만들지 않았고, 노트 ID·derived-from 좌표는 유지했습니다. 현재 대화 지식으로 쓰려면 별도 원문 검증이 필요하다는 조건을 남겼습니다. 전체 자동 수집이나 과거 Raw의 재작성은 수행하지 않았습니다.

세 번째 활성 화자 관측은 legacy 자동 본문과 같지 않아 전문을 치환하지 않았습니다. 정확한 세 원문이 같은 계정·방·화자에 연결되는 것을 읽고, 과거 8142건 표기와 현재 색인의 8148건을 구분했습니다. 유일한 자동 수량 문장을 역사적 값으로 한정하는 앵커 수정과, 인용된 주장/명령이 검증된 사실·실행 지시가 아니라는 경계만 추가했습니다. 다른 본문·세 인용·제목·근거 좌표는 그대로 남겼습니다. 표시 이름과 사람이 직접 쓴 발화인지 여부는 확정하지 않았습니다.

수정 후 새 구간과 SHA를 다시 읽었습니다. 실제 pinned MCP surface의 read_node도 같은 파일의 view_hash를 반환했고, 원문 대조와 의미 한계를 SDK 조직 review의 checked에 기록했습니다. 전체 outcome은 deferred로 유지했습니다. 세 단위의 부분 진척으로 remaining은 103→100이며 전체 corpus 증류·조직 완료를 뜻하지 않습니다.

| 확인 | 결과 | 범위 |
|---|---|---|
| inactive 정확한 자동 본문 정정 | 2개 | 원본 byte backup·CAS·동일 ID/derived-from |
| 활성 관측 앵커 한정 | 1개 | 수동 본문/인용/제목/근거 좌표 보존 |
| native 조직 검토 | 3개 checked, 100개 remaining | 현행 구간/SHA, deferred |
| 실제 SDK 통합 회귀 | 47개 통과 | 정본 요약·캐시 배제·system-only 범위 포함 |
| 영향 경로 회귀 | 130개 통과 | corpus/source/delta/voice/SDK |
| native 정본 validator | 22 pass, 0 fail, 0 skipped | 기존 governance 경고는 별도 유지 |

이 작업은 원문 관측의 출처·시점·불확실성 경계를 고친 것입니다. 인용된 기술 주장이나 화자 정체를 독립적으로 사실 승인한 검사가 아닙니다. 새 성능 개선율, 물리 UI/음성, Flash-Next·Dot·공증·production 완료를 주장하지 않습니다. 이전 측정 자료는 각 고정 snapshot과 판본에 묶이며, 정본이 바뀐 뒤 그 재현은 새 상태를 과거 표본으로 간주할 수 없습니다.
