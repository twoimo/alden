# Exact model identity and worker readiness — 2026-10-09

The CLI previously mapped explicit Gemini 3.8 IDs to its Gemini 3.7 variant. Remote preflight could succeed by probing a different model, checking only an executable version, accepting an API-key error, or falling back from the selected OpenCode model to Gemini. Those outcomes did not prove readiness of the selected model.

Gemini 3.8 now has a distinct selection and retains its canonical 3.8 ID with high effort through OpenCodex. The explicit current/short aliases normalize to that same version. The router Responses endpoint receives the exact selected model and effort; success requires HTTP 200, a bounded valid JSON response, completed status, the selected model identity (canonical or provider suffix), and the exact synthetic probe answer. Failure stays a failure; no alternate-provider probe or executable-version success substitutes for the selected route. Legacy Gemini and OpenCode errors no longer silently become success or trigger a different model fallback.

Validation: full CLI tests 249 passed/1 ignored, strict Clippy, version/effort mapping cases, and bounded response-validation cases covering quota errors, wrong model, incomplete status and malformed responses. A real synthetic OK request returned gemini-3.8-flash with completed status through the current router. This is a model-route check, not private conversation transmission or a message send.

A new immutable runtime was prepared for the existing three targets, with 43 assets whose hashes/modes were read back. Its private configuration snapshot follows the already selected Gemini 3.8 Flash/high profile; all other configuration values and selector order were retained. Preparation updates the existing fixed CLI executor as prescribed by the packager; it does not start the session. Existing enrollment, queues and the old watchdog process were preserved. The new runtime's actual pinned Python imported and exercised the dated-retrieval helper.

Read-only foreground preflight initially required an already-open exact KakaoTalk window. During the window check an exclusive existing supervisor owner lock prevented automatic worker startup. The verification-opened window was closed and the lock released. Preflight then reported invalid leftover supervisor proof for existing room state, with will_send=false and workers_started=false. Predicate results and original private outputs were retained. No status proof was fabricated, queue deleted, pending send retried or session activated. Actual worker transition remains incomplete until this state is reconciled through supported evidence-preserving recovery; a generic build or model response does not prove that transition.

Private evidence lives in the task outputs/worker-runtime-20261009 directory. Broader multi-source acquisition, independent real-source evaluation, physical voice/input, DPO, Archify and final signed/notarized production delivery remain part of the full active objective.
