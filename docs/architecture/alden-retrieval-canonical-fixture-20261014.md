# 검색 평가 ID 호환성 정정

이전 평가에서 관찰한 날짜 관계·환불 의미 질의의 공개 컨텍스트 출처 누락은 제품 결함으로 확정되지 않았습니다. 과거 합성 자료는 `topic:` ID 11개를 사용했고, 제품 그래프 탐색은 `ent:`, `chat:`, `person:`, `time:`, `author:` 접두사를 받습니다. 이 조건 차이를 확인한 뒤 제품 필터를 바꾸지 않고 새 v3 평가 자료에서 ID를 일대일 대응시켰습니다.

v2의 23개 엔터티·3개 관계·27개 질의와 숫자 ID의 published snapshot을 보존했습니다. 대응을 역으로 적용하면 원래 corpus의 모든 의미 필드와 전체 질의 판단, snapshot이 정확하게 복원됩니다. source_event_ids·evidence_message_id·expected_evidence_ids는 검색 엔터티 ID와 다른 식별자이므로 변경하지 않았습니다. v1/v2 파일 SHA와 보존 증거는 identity-map 및 별도 실행 영수증에 남습니다.

기본 평가 경로는 [v3 자료](../../tests/fixtures/alden-retrieval-v3/README.md)를 사용합니다. canonical 정책이 선언된 자료에서 미지원 접두사나 공백 ID·truthy 비불리언 선언은 실패합니다. 과거 자료를 명시하면 legacy 정책·미지원 ID를 표시합니다. 각 보고서는 corpus/queries/identity-map SHA와 제품 검색 코드 SHA에 결속합니다.

부모 작업의 관련 25개 테스트와 실제 명시 CLI 평가를 완료했습니다. 새 자료는 dev12/heldout15의 합성 질의 27개를 포함합니다. `fixture-rrf`의 기대 출처 전달률과 컨텍스트 Recall은 1.0, 중복 후보 질의율과 금지 자료 누출은 0이었습니다. 날짜 관계·환불 의미 질의의 두 출처 누락도 재현되지 않았습니다. `bm25`의 컨텍스트 Recall은 0.9583, 기대 출처 전달률은 0.9333이며 붙여 쓴 한국어 질의의 기대 출처는 여전히 누락됩니다.

이 수치는 제공된 합성 자료와 고정 Dense 순위에 한정됩니다. v2에서 거절되던 ID를 호환시키고 결과를 대사한 것이므로 검색 성능 향상으로 계산하지 않습니다. 실제 E5·ANN·생성 모델·원문 의미/인용 정확성이나 설치 앱 품질로 확대하지 않습니다. 제품 검색 코드 SHA는 이전과 동일한 `88537df2cd7a718fc100225ced9250afc68c6359cb81922afb38ab362814d18b`이며 설치 앱은 0.3.102/runtime093b6d1을 유지합니다.

추가로 이미 실행 중인 loopback E5 서비스의 `loaded=true`, `state=ready`, embedding capability를 확인한 뒤 명시 `live-rrf` 평가를 한 번 수행했습니다. 모델은 `mlx-community/multilingual-e5-small-mlx@5030c7625865046d350eeea28f427d80353d0ac0`으로 고정했고 새 모델·프로세스·서버 재시작·공유 설정 변경은 하지 않았습니다. 합성 fixture와 기존 bootstrap 항목을 포함한 임시 색인 31개를 생성했으며 영속 운영 색인은 변경하지 않았습니다.

실제 E5를 사용한 27질의는 Recall@3/nDCG@3, 컨텍스트 Recall 및 기대 출처 전달률 1.0, 중복 후보·금지 자료 누출 0으로 관측됐습니다. 24개 positive 질의의 Recall@1은 0.9375였습니다. 같은 과정의 공개 bundle 검색 지연은 n=27의 p50 26.204ms/p95 29.941ms, 별도 임시 색인 생성은 145.431ms입니다. 이 수치는 warm 로컬 서비스·작은 임시 그래프의 범위이며 전체 앱/음성/생성 지연이나 생산 백분위가 아닙니다. 실제 인코더 호출 증거를 고정 Dense 순위 결과와 구분하며, 사람 의미 gold·넓은 운영 자료·EmbeddingGemma2 멀티모달·학습·제품 승격은 여전히 검증 전입니다. v2→v3 성능 비교나 다른 모드와의 속도 향상을 주장하지 않습니다.

요청하신 Web GPT-6/xhigh 병렬 검토는 ID 일대일 대응·참조 무결성·split 보존·출처 전달의 독립 확인 조건을 제시했습니다. 검토자의 현재 소스 재조회는 도구 미제공으로 실패했으므로 제공 계약과 이전 소스에 근거한 추론입니다. 현재 평가기가 공개 출처를 확인하지 않는다는 부분은 최신 코드와 달라 채택하지 않았습니다. 실제 소스·보존·실행 검증은 부모 결과를 사용하며, 이전에 차단된 검토자 재현 명령은 재시도하지 않았습니다.

전체 목표의 실제 원문·동일인·시간·철회·인용 의미 평가와 여러 호스트·물리 장치·학습·정식 배포 요구는 계속 남아 있습니다.
