# Alden 0.3.50: 응답과 이미지 입력 경계

## 원인과 수정

OpenCodex 어댑터의 JSON 응답 경로는 본문을 읽자마자 완료로 표시했다. 다른 모델, 실패·미완료 상태와 용량 초과도 응답 텍스트가 있으면 성공할 수 있었다. 스트리밍 경로도 완료 이벤트 내부 상태와 누락된 모델을 확인하지 않았다. 재현 로그는 별도 작업 공간의 `outputs/media-response-20261009/reproduction.log`에 보존한다.

두 형식 모두 선택 모델의 전체 ID 또는 라우터가 반환하는 동일 모델의 제공자 접두부 없는 ID, `status=completed`, 오류·미완료 사유 부재를 확인한다. 응답은 1MiB, 스트리밍 한 줄은 64KiB로 제한한다. 완료 응답 ID·사용량을 두 형식에 같은 방식으로 연결하고, 취소된 턴의 텍스트는 반환하지 않는다. 제공자 오류 본문과 비밀값은 오류 문구에 복사하지 않는다.

파일·이미지·프롬프트 오류는 제공자의 가용성을 증명하지 않는다. 입력 단계의 실패는 모델 상태 파일을 바꾸지 않으며, `image_input_unavailable`·`image_input_budget` 등 원인을 보존한다. 워커는 두 이미지 입력 오류를 제공자 장애와 구분해 기존 재시도·교체 금지 경계를 유지한다.

이미지는 심볼릭 링크를 따라가지 않는 regular-file descriptor로 한 번 읽는다. 크기·수정 시각·inode를 읽기 전후와 경로에서 대조하고 PNG/JPEG/GIF/WebP 헤더로 MIME을 결정한다. 전송 바이트와 metrics의 SHA256·크기·MIME이 동일하다. 최대 4개·각 8MiB·합계 20MiB이며, 개인정보가 될 수 있는 경로는 metrics에 기록하지 않는다. 형식 헤더 검사는 전체 픽셀 디코딩 성공의 증명이 아니다. 기존 첨부 출처 검증과 제공자 디코딩은 별도 단계다.

## 검증과 전달 경계

JSON·SSE의 완료/실패/모델 불일치, 잘못된 JSON 구조, 응답 용량, 누락 이미지, 링크 파일, 확장자와 실제 형식 차이, 읽는 도중의 파일 교체, 이미지 개수/합계 용량, 늦은 취소와 워커 오류 전달을 검증한다. 기존 사진 후속 질문·문서 파싱·음성 턴·모델 상태·새 워커 패키징을 포함한 집중 검사 151개가 통과했다. 고정 Python 런타임과 UI·Rust·설치본 결과는 전달 영수증에서 각각 대조한다.

설치된 Resources에서 합성 이미지와 해당 대화의 짧은 후속 질문을 선택된 Gemini Flash high로 확인한다. 실제 라우터 추론은 모의 JSON 응답 검사와 구분한다. 이 검증은 카카오톡 실제 수신·전송이나 사용자의 물리 입력을 대신하지 않는다. 기존 감독자 증빙 오류로 막힌 운영 워커의 활성화, 여러 제공자의 실제 추론, 물리 음성·마이크·잠금·GPU/배터리 측정과 정식 서명·릴리즈·프로덕션 배포는 전체 TODO에 남아 있다.

현재 공식 [Responses 계약](https://developers.openai.com/api/reference/resources/responses/methods/create)과 [스트리밍 이벤트 설명](https://developers.openai.com/api/docs/guides/streaming-responses)을 2026-10-09에 확인했다. OpenAI Docs 스킬과 실제 OpenCodex 응답은 별도 근거이며, 공식 문서가 라우터의 모든 모델 지원을 증명하지 않는다.
