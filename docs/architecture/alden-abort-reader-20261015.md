# 요청 범위 중단 상태 리더

설치0.3.117/20b23f0의 독립 `collection-affinity` 조회는 `affinity_cpu_budget`으로 실패했다. CPU8.001427초/경과15.185393초이며 후보를 공개하지 않았다. 계측 진단은8초 제한을 그대로 유지했고 중단 조회26,895회에서 반복 root open과 JSON 파싱 비용을 확인했다. 진단 실행의 계측 비용을 정상 실행과 직접 비교하지 않는다.

`alden_abort.abort_state_reader`는 요청 동안 검증한 root FD 하나를 유지한다. 매 호출에서 경로를 symlink를 따라가지 않고 stat해 디렉터리·실행 사용자 소유·0700·dev/inode를 확인한다. 상태 파일은 매번 openat/O_NOFOLLOW/NONBLOCK/CLOEXEC로 다시 열고 regular·소유자·0600·nlink1·4096바이트 제한 및 실제 바이트를 검사한다. 정확히 같은 바이트에만 frozen 상태 파싱을 재사용한다. 파일 metadata나 시간에 따른 캐시와 폴링 간격 변경은 없다.

처음 없는 root는 다음 호출에 다시 확인한다. 한 번 고정된 root의 교체·삭제·권한 오류는 요청 안에서 계속 중단 상태로 반환한다. 파일 읽기 전후 root를 검증하고, read/close는 요청별 lock으로 직렬화한다. 정상·예외 종료 모두 FD를 닫고 종료 뒤 콜백은 중단 오류를 반환한다. 기존 단발 리더와 writer의 기본 동작은 유지한다. 적용 범위는 메뉴의 `collection-affinity` 요청이다.

첫 수정 소스의 실제1984개 노드 조회는 CPU6.323490초/경과11.522365초에 완료했다. 기존 성공117캡처와 후보1024개·노드 근거·입력 범위·binding·coverage·budget·revision이 모두 같았다. 시간과 SQLite bookkeeping은 동등성 대상에서 제외했다. 기존 실패는 별도 보존하며 단발 관측을 냉간/p95 보장이나 전체 앱 향상률로 확대하지 않는다.

private 파일20,000회씩 기존/수정 ABBAABBA, 각4묶음의 median CPU는0.9257965→0.604386초, median wall은1.042660→0.676135초였다. 이는 같은 private 상태의 리더 microbenchmark이며 실제 그래프 전체 속도나 배터리 결과가 아니다. 원래8CPU/20wall/128MiB·노드/쌍/제품/바이트 제한과 중단 확인 빈도는 그대로다.

기존 관련311검사와 추가 보안/기존 중단24검사가 통과했다. 새11개 테스트는 즉시 본문 변경·원자 교체·권한/owner/link/FIFO/symlink/용량/UTF8/중복JSON·root 교체/삭제·읽는 중 교체·예외 FD정리·동시 close를 검증한다. 별도 private 중단 컨트롤러로 실제 collection 조회의17번째 확인에서 취소하고 후보가 공개되지 않는 것을 확인했다. 전역 비상 상태는 변경하지 않았다. root 검증이 예외로 끝나 아직 호출자에게 반환하지 못한 FD도 닫도록 기존 helper를 보완했다.

검증·설치 단계와 실패는 `outputs/abort-reader-20261015/`에 보존한다. Astra/max 독립 보안 검토를 진행 중이며 앞선 두 에이전트는 중단되어 완료 결과로 세지 않는다. 설치118·정식 서명/공증·배포 및 물리 단축키 동작은 이 소스 설명으로 확인되지 않는다. 전체18 목표와 라벨 읽기 승인 대기를 유지한다.
