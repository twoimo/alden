## 2. 부모가 호출할 API

```ts
import { SemanticLayoutEngine } from './knowledge/semantic-layout';

const engine = new SemanticLayoutEngine();
const result = engine.layout(
  view,                       // KnowledgeView
  previousPositions,          // ReadonlyMap<string, Point3>
  view.layoutAffinity?.pairs ?? [], // 검증된 LayoutAffinityPair[]
  { changedIds, pinnedIds, reflow: false, nowMs: snapshotTimeMs },
);
// result.anchors: Map<string, Point3>
// result.clusterIds: Map<string, string>
// result.dirtyIds: Set<string>
// result.diagnostics: SemanticLayoutDiagnostics
```

세 번째 인수를 생략하면 `view.layoutAffinity?.pairs`를 사용한다. 명시적으로 `[]`를 전달하면 S를 제거한 R-only 갱신이다. 엔진 인스턴스는 동일 권한 범위의 스냅샷 사이에서 재사용한다. 매 프레임 새로 만들거나 호출하지 않는다. 이전 좌표와 반환 Map의 항목은 복사하므로 호출자가 결과를 수정해도 내부 위치 캐시를 손상시키지 않는다.

`changedIds`는 명시적인 국소 재계산 요청이다. R/S의 추가·변경·제거는 힌트 없이도 자동 검출한다. 단순 label/source/space 표시 변경에 이 힌트를 넓게 넣지 않는다. `pinnedIds`는 이전 유한 좌표를 정확히 유지한다. 중요도나 큰 질량을 핀으로 대신하지 않는다. 핀을 해제하면 그 영역이 다시 계산 대상이 된다.

`nowMs`는 해당 스냅샷에서 관계의 유효 시간을 판정할 기준이다. 생략하면 호출 시각을 사용한다. 재현할 때는 동일 기준 시각을 전달한다. 계산된 `clusterIds`는 배치용 불투명 식별자이며 엔터티 ID·프로젝트·의미 정답 라벨이 아니다.

**권한·계정·범위가 달라지면 부모가 `engine.clear()`를 호출하거나 새 인스턴스를 사용해야 한다.** 엔진은 전달받은 후보의 수치·endpoint를 검사하지만 권한·현재 버전·출처·프로필 근거를 스스로 조회하거나 재검증하지 않는다. 부모의 `LayoutAffinity` 검증과 epoch 검사를 통과한 후보만 전달해야 한다. 타입 선언만으로 실제 검증이 완료됐다고 간주하지 않는다.

부모는 카메라, 선택, 탐색 이력, 권한별 이전 좌표를 관리한다. 엔진은 이 상태를 읽거나 수정하지 않는다. 탐색 이력에서 캐시를 복원할 때도 현재 권한과 버전에 대한 재검증이 먼저다.

## 3. R/S와 군집 계산

R은 현재 노드 집합 안에 있는 유효한 명시적 관계다. self-link, 철회, 만료·미래 관계, 비유한·0 이하 weight, navigation은 계산 기여가 0이다. 양 끝을 정렬한 별도 배치용 쌍을 만들고 같은 쌍의 최대 강도를 사용한다. 원래 graph의 source→target, relation type, context, 근거, 복수 관계는 변경하지 않는다. 따라서 관계의 방향만 뒤집혀도 물리상 근접성이 같을 수 있다. 이는 사실 관계의 방향을 지운다는 뜻이 아니다.

S는 `{source,target,cosine}` 후보를 별도 채널로 사용한다. endpoint가 현재 노드 집합에 없거나 self-pair, 비유한 값, 0 이하 코사인, 1 초과 코사인은 계산에서 제외한다. 음수 코사인을 반박 관계나 음의 사실 가중치로 바꾸지 않는다. 모델·가중치·임베딩·프로필을 생성하거나 바꾸지 않는다.

S 후보를 코사인 내림차순과 안정 ID 동점 규칙으로 정렬해 양 끝의 S degree가 각각 4를 넘지 않도록 선택한다. 이는 정확한 mutual kNN을 새로 계산한 결과가 아니라, 부모가 제공한 후보에 적용하는 제한된 탐욕 선택이다. 선택에서 빠진 수를 진단으로 돌려준다. 동일 문구나 허브가 후보를 독점하는 문제를 완전히 해결하는 방식이라고 주장하지 않는다.

각 채널의 가중 degree를 따로 계산해 정규화한다. R 강도는 `1 - 1 / (1 + weight)`이고 S 계수는 `.25`다. 군집 입력은 정규화한 R과 S의 합이다. 전체 그래프의 가중치 총합을 사용하지 않고 **현재 연결 성분별 총합**으로 modularity 이동 점수를 계산한다. 따라서 무관한 다른 연결 성분의 링크 수가 늘어도 기존 군집의 해상도는 바뀌지 않는다.

최대 8회 순회하며 정해진 ID 순서와 동점 규칙으로 양의 점수 개선만 허용한다. 기존 군집 라벨에서 시작하되, 분리될 수 있도록 단일 노드 군집도 후보로 둔다. 0점 동점 때문에 불필요하게 라벨을 바꾸지 않는다. 횟수 제한 안에서 얻은 국소 결과이며 전역 최적해를 보장하지 않는다.

최종 군집과 이전 군집의 구성원 겹침을 비교해 겹침이 큰 순서로 기존 ID를 이어받는다. 한 이전 ID를 여러 새 군집에 중복 할당하지 않는다. 대표 노드가 삭제돼도 남은 구성원으로 ID와 중심을 유지한다. 신규 군집만 구성원 ID에서 초기 중심을 결정한다. sourceTarget/space/label/category와 출처 개수는 중심이나 군집 가중치에 사용하지 않는다.

## 4. 목표 좌표와 증분 유지

이전·현재의 유효 R/S 쌍을 비교하고, 변한 쌍의 양 끝·신규 노드·명시적 changedIds·핀 상태 변경을 시작점으로 삼는다. 이전·현재 연결 성분의 합에서 이 시작점과 연결된 영역만 영향을 받는다. 링크가 철회되거나 노드가 삭제돼 끊긴 양쪽 영역도 재검토한다. 영향 영역 밖의 기존 유한 좌표는 정확히 복사해 유지한다.

영향 영역은 최대 2048개까지 커질 수 있다. 한 실제 관계가 큰 연결 성분에 걸려 있으면 dirty 수가 120을 넘을 수 있으며 이를 숨기지 않는다. 엔진의 dirty 집합과 부모의 120개 국소 물리 예산은 다른 개념이다.

일반 갱신은 이전 위치에서 시작하고 기존 군집 중심을 유지한다. 신규 노드는 군집 중심에 ID로 정한 작은 오프셋을 더해 시작한다. 핀과 영향 영역 밖의 위치는 이동하지 않는다. 입력 순서나 무관한 출처 추가에 따라 전체 배율을 다시 맞추지 않는다. 120→121개 분기도 없다.

`reflow: true`는 명시적 전체 재배치다. 현재 군집을 다시 계산하고 중심을 다시 배치하며 모든 비핀 노드를 계산한다. 군집 ID는 가능한 한 기존 구성원 대응을 유지하지만 좌표 유지 조건은 해제한다. 핀은 이 경우에도 보존한다.

위치 계산은 스냅샷마다 최대 32단계다. 군집 중심 인력 `.12`, 이전 위치 유지 `.08`, R/S 스프링, 공간 근접 충돌 분리를 계산하고 단계 이동량에 상한을 둔다. 비핀 계산 좌표의 타원체 범위는 `(2.3,1.55,1.1)`이다. 보존 좌표와 핀은 임의로 자르지 않고, 큰 외부 좌표는 내부 힘·격자 계산에서 범위가 제한된 좌표로 사용한다.

degree 정규화로 전체 가중치 변화가 상쇄되더라도 목표 거리에는 원래 강도가 반영되도록 했다.

```text
u = 1 - 1/(1 + realWeight)
r = u / sqrt(max(1, realDegree_i) * max(1, realDegree_j))
s = .25 * cosine / sqrt(max(1, semanticDegree_i) * max(1, semanticDegree_j))
lR = .3 + .45*(1-u)
lS = .9 - .25*cosine
rest = (r*lR + s*lS)/(r+s)
F_i = 2*(r+s)*(distance-rest)*(x_j-x_i)/distance
F_j = -F_i
```

원래 강도가 rest length에 반영되지 않으면 높은 degree에서 모든 코사인·weight를 같은 비율로 바꿨을 때 정규화가 변화를 지울 수 있다. 이 반례를 별도 회귀로 고정했다. 0weight/navigation은 스프링 자체를 만들지 않으므로 현행 Plasticity의 최소 stiffness와 같은 의미로 취급하지 않는다.

같은 좌표의 동점은 ID 쌍으로 정한 작은 방향을 사용한다. R/S가 없는 서로 다른 노드도 공간 충돌로 분리할 수 있지만 이 작업은 의미 근거나 사실 관계를 생성하지 않는다. 동일 문구·코사인 1인 노드도 별도의 엔터티로 남긴다.

`dirtyIds`는 입력의 이전 유한 좌표가 없거나 목표 좌표 차이가 `1e-9`를 넘는 노드다. 현재 표시 집합만 반환하며 삭제된 노드는 결과와 캐시에서 제거한다. 32단계 완료, 유한 좌표, dirty 계산 완료는 물리 평형·화면 정지·의미 품질 합격을 뜻하지 않는다.

## 5. 작업량·공간·캐시 예산

| 항목 | 고정 상한 |
| --- | ---: |
| 반환·보유 노드 | 2048 |
| 검사하는 입력 노드·R 행·S 행 | 8192 / 32768 / 32768 |
| R 쌍·S 쌍 | 각 4096 |
| 노드당 S degree | 4 |
| 커뮤니티 순회 | 8 |
| 위치 계산 단계 | 32 |
| 전체 호출의 충돌 거리 검사 | 131072 |
| 한 격자 셀에 보관하는 충돌 후보 | 16 |
| 영속 위치·군집 라벨 | 각 2048 |
| 영속 유효 쌍·군집 중심 | 최대 8192 / 2048 |

격자 크기는 `.16`이며 인접 27개 셀만 검사한다. 충돌 예산은 단계마다 다시 주어지는 값이 아니라 전체 호출의 합계다. 셀 후보가 잘리면 `collisionCandidatesTruncated`, 전체 예산이 끝나면 `collisionBudgetExhausted`를 표시한다. `crowdedCells`는 상한을 초과해 생략된 셀 항목의 누적 관측 수다. 이를 정확한 미해결 충돌 수나 고유 과밀 셀 수로 사용하면 안 된다.

정렬과 커뮤니티 계산은 입력·노드·희소 쌍 예산 안에서 수행하며 모든 2048개를 매 프레임 O(V²) 물리로 돌리지 않는다. 커뮤니티 이웃 방문은 `2*8*(R+S)`, 스프링 계산은 `32*(R+S)` 이하로 검사한다. 입력 검사 상한을 넘으면 `inputTruncated`를 표시한다. 이 경우 입력의 앞부분만 처리하므로 잘린 입력 전체에 대한 순서 불변성이나 완전성을 주장하지 않는다. 부모의 정상 overview·검증된 후보는 이 검사 예산 안에 있다.

노드 상한에 도달하면 살아남은 캐시 ID를 신규 ID보다 우선하고 신규 항목을 안정 ID순으로 받는다. 상한 밖 도착 항목으로 기존 노드를 밀어내지 않으며 생략 수를 보고한다. 외부 previousPositions Map 전체를 저장하지 않고 현재 선택된 ID만 읽는다. 삭제 노드 위치, 삭제 endpoint 쌍, 사용되지 않는 중심은 호출 끝에서 모두 제거한다. 동일 권한 범위의 보통 삭제에서는 공간 기억을 위해 살아남은 군집의 중심을 유지하므로, **권한 철회 시에는 부모의 clear가 반드시 필요하다.**

## 6. 부모의 보간·120 물리와 연결

부모는 검증된 스냅샷에 대한 엔진 결과를 모든 표시 노드의 목표로 반영하고 dirty 집합에 대해서만 위치 보간을 수행한다. 기존 `PlasticityLayout`은 최대 120개 국소 노드로 유지한다. 배열 앞 120개만 갱신하고 나머지 기존 노드를 새 앵커로 반영하지 않는 방식은 사용하지 않는다.

초기 전체 계산은 동기 API지만 실제 측정 p95가 100ms를 넘는다. 따라서 부모가 worker나 별도 계산 경로에서 호출하고, 결과 적용 전에 epoch·현재 버전·권한 범위 일치를 검사해야 한다. 메인 스레드에서 직접 호출하면 UI p95 100ms 목표를 충족했다고 말할 수 없다. worker 연결, 메시지 복사 비용, 설치 화면 검증은 이 작업 범위 밖이다.

동일 스냅샷을 반복해 받으면 dirty 0이며 군집 순회·스프링·충돌 단계가 실행되지 않는다. 부모의 parser/controller signature 검사를 재사용해 불필요한 호출도 억제한다. engine 계산 완료, dirty 보간 완료, 국소 physics 정지, 화면의 render 정지, 의미 정답 평가를 각각 기록한다. S를 사실 edge, 활동 이벤트, 학습 결과로 변환하지 않는다.

## 7. 회귀와 실제 자료 측정

전용 `semantic-layout.test.ts`의 22개 검사가 통과했다. 핵심은 다음과 같다.

- 120→121개 전환과 무관한 source/space/label 변경에서 기존 좌표 유지.
- 노드·R·S 입력 순서 변경의 결정성, 무관한 ID 교체의 지역 유지.
- R-only/S-only/R+S의 군집·목표 변경과 원래 graph 불변성.
- R 추가·가중치 변경·철회와 S 코사인 변경·제거 자동 검출.
- 높은 degree에서 정규화로 원래 강도 변화가 상쇄되는 반례.
- 0weight/navigation/0 이하 코사인의 군집·스프링 기여 0.
- 연결 없는 동일 좌표의 결정적 분리와 별개 엔터티 유지.
- 핀·명시적 reflow, 동일 스냅샷 no-op, 대표 삭제 후 군집 ID 유지, 캐시 제거.
- 2048개 용량, 허브 S degree와 충돌·계산 횟수 상한, 잘린 충돌 후보의 정직한 진단.

대상 엔진·테스트의 `--noEmit --strict --noUnusedLocals --noUnusedParameters` 타입 검사도 종료 코드 0이었다. 전체 앱 빌드나 설치 앱의 테스트와 구분한다.

측정 환경은 Apple M5 Max, macOS arm64, Node `v26.10.0`, TypeScript `5.9.3`이다. 각 실제 자료 조건은 준비 실행 5회와 새 엔진의 측정 25회로 구성했다. JSON 읽기·TypeScript 메모리 변환·모델 추론은 측정 구간에 포함하지 않는다. 아래 시간은 엔진 호출과 유한값·예산 검사까지 포함한다. CPU는 해당 측정 구간의 프로세스 누적 user+system 시간이며 설치 앱의 지속 CPU 퍼센트가 아니다.

| 실제 R-only | 실제 1984 | 3761 / 0 | 130.378 / 208.193 | 3829.834 + 200.033 | 1984 |

2048개 용량 조건은 준비 3회·측정 10회다. **제공된 실제 파일에는 1984개만 있으므로 2048개 모두 실제 자료라고 보고하지 않는다.** 합성 64개는 용량과 유한값·예산 검사에만 쓰며 실제 의미 품질 평가에는 사용하지 않는다.

S 1024쌍 중 604쌍을 degree 예산 안에서 사용하고 420쌍은 잘린 후보로 보고했다. 실제 R 3789행은 무방향 중복 쌍 집계 후 3761쌍이다. R과 S가 같은 endpoint를 가질 수 있어 결합 캐시 쌍 수는 4350이다. 모든 측정에서 좌표는 유한하고 노드·영속 캐시·순회·스프링·충돌 상한을 지켰다.

최종 실제 R+S의 군집 수는 310, community 순회는 4회·이웃 방문 34800회, 스프링 계산 139200회였다. 군집 수가 정답이나 품질 개선을 뜻하지 않는다. 초기 전체 측정은 충돌 검사 131072회 예산이 소진됐고 일부 조건에서는 셀 후보도 잘렸다. 충돌이 모두 해결됐거나 수렴했다고 선언하지 않는다.

동일 스냅샷은 affected/dirty 0, solver·스프링·충돌 0이었다. 무관한 출처의 노드 1개 추가는 affected/dirty 1이며 기존 1984개 좌표가 정확히 같았다. 실제 R 가중치 1개 변경은 affected/dirty 402였고, S-only에서 코사인을 `.8`배로 변경하면 affected/dirty 419였다. 이 수치는 실제 자료를 입력한 구조 검증이며 코사인 변화가 실제 의미 변화의 정답이라는 뜻은 아니다.

이전 출처 시드 배치와 동일 조건의 A/A·전후 성능 비교는 수행하지 않았다. 시간 차이를 개선율로 보고하지 않는다. 실측 p95가 앞선 제안의 500ms 계산 예산 안에 있다는 사실과 실앱 입력·프레임·정착 목표를 만족한다는 주장은 별개다.

## 8. 남은 평가와 정확한 한계

허브 정규화와 S degree 제한은 후보 편향을 줄이는 기계적 장치다. 같은 문구의 다른 사람·회사, 같은 출처의 무관한 내용, 다른 출처의 같은 논점, 정정·반박·시간 차이, 실제 허브를 포함한 독립 금표가 필요하다. 동일 문구를 엔터티 병합 근거로 쓰지 않으며 이름만으로 의미 라벨을 만들지 않는다.

이 엔진은 코사인을 계산하지 않고 검증된 후보값을 입력받는다. 정확한 cosine, 모델·입력 역할·pooling의 호환성, 후보 recall, 현재 권한·버전·출처 결합은 부모의 벡터·검증 경로와 독립 평가가 담당한다. 부분 S coverage와 420개 후보 잘림이 의미 품질에 미치는 영향은 미검증이다. S 자체를 정답으로 삼아 S의 품질을 자기 평가하지 않는다.

이 구현의 완료는 API, 제한된 군집·목표 계산, 전용 회귀, 실제 자료의 유한값·dirty·예산·CPU 검증이다. 부모의 연결, 실제 UI 렌더와 정착, 독립 의미 품질, 빌드·설치·배포까지 완료했다고 보고하지 않는다. 설치 Resources 실행이 후속으로 필요하면 기존 pinned Python과 `-B` 조건을 지켜야 한다.

전달 근거는 `outputs/semantic-layout-engine-20261009/test-results.json`, `benchmark-results.json`, 재현용 `run-tests.mjs`, `benchmark.mjs`다. 초기 S 결합 오류의 결과도 따로 보존했다. 문서·검증 기록 외의 공유 파일은 이 작업에서 수정하지 않았다.
