# Alden 0.3.98 — 선언된 날짜·시간대·단위의 표기 정규화

품질 확인은 허용된 현재 버전의 메타데이터에서 명시적인 발행·작성·갱신·관측·유효 기간 필드와 구조화된 `quantity`/`quantities` 값만 해석한다. 본문·파일명·URL·원본 ID에서 단위나 시간 역할을 추정하지 않는다. 원문·ID·출처·관계·현재 버전과 검색/그래프 기존 규칙을 유지하며 별도 표기 해석을 계산한다. 변환 규칙은 `source-declared-time-v1`, `source-declared-quantity-v1`, 집계 규칙은 `source-declared-fields-v1`이다.

날짜만 있으면 날짜 정밀도를 유지하며 자정·UTC 시각을 만들지 않는다. 명시적인 UTC/숫자 오프셋만 UTC로 변환하고, 시간대 없는 시각에 Mac 시간대를 적용하지 않는다. 6자리보다 정밀한 소수초·자연어·시간대 약어·확장 suffix는 해석하지 않는다. UTC 표현 `Z`/`-00:00`의 알려진 UTC와 현지 오프셋 미상을 구분한다. ISO `24:00`은 다음 날짜의 경계로 계산하며, 윤초는 실제 문맥 없이 일반 datetime으로 바꾸거나 잘못된 시각으로 표시하지 않는다.

단위 표는 대소문자를 유지하는 27개 명시 기호로 제한한다. Decimal로 질량 g·길이 m·시간 s·데이터 bit를 계산하며 SI/IEC 접두사를 구별한다. 숫자와 단위가 없는 기록, 해석 불가·잘못된 값, record당 16개 검사량을 넘긴 선언을 분리한다. 같은 값으로 변환됐다는 이유로 다른 문서·사람·상품·주장을 병합하지 않는다. 원문은 바꾸지 않고 의미상 동일성·물리적 타당성·발행 사실·효력을 인증하지 않는다.

공식 근거는 [BIPM SI 접두사](https://www.bipm.org/en/measurement-units/si-prefixes), [IEC 단위 표기](https://styleguide.iec.ch/?docs=iec/typographic/units-and-symbols), [RFC 3339](https://www.rfc-editor.org/rfc/rfc3339)와 그 개정 [RFC 9557](https://www.rfc-editor.org/rfc/rfc9557)이다. 공통 datetime의 좁은 지원 범위이며 전체 ISO/IXDTF/IANA 시간대·윤초 데이터베이스 구현은 아니다.

실제 허용된 5개 프로젝트의 26,625개 현재 기록에서 시각 필드1,468개를 관찰했다. 날짜만 있는1,006개·UTC/오프셋3개를 해석했고 explicit missing459개와 선언이 없는25,157개를 구별했다. UTC가 알려져 있지만 현지 오프셋이 명시되지 않은1개도 별도로 집계했다. 구조화된 값·단위 선언은0개이며 기존 본문 속 모든 단위를 해석했다는 뜻이 아니다. 기존 범위·수량·무결성·본문/중복/메타데이터/벡터 지표는 비교에서 동일했다. 실제 단위 자료의 제품 흐름은 별도 미결이다.

Web GPT-6/xhigh 두 worker가 분리된 날짜/단위 파일을 작성했고 실제 turn_context와 종료를 확인했다. 부모가 source·테스트·통합과 표준 대조를 수행했다. 새 표준 세 반례는 수정 전3실패였으며 수정 후 통과했다. 최초 품질 검사 계약7실패와 UI 빈 보고서1실패는 새 집계 계약/빈 fixture에 맞춰 수정했고, 잘못된 시스템 Python의 menu bytecode 오류와 두 잘못된 직접 호출도 실행 기록에 남겼다. 보호 원본이나 설정·큐·운영 worker를 수정하지 않았다.

소스·실제 read-only 검사·후보/설치·직접 화면·CI·보존·배포물은 `outputs/graph-identity-semantics-20261013/`에서 별도로 검증한다. 원문 의미 gold·동일인·별칭·시간 효력/철회·자동 병합·전체 GraphRAG/호스트/음성·정식 배포의 전체 목표는 유지한다.
