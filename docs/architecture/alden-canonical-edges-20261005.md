# 저장 참조와 답변 근거

0.3.24의 실제 설계 질의에서 저장된 세 전제 중 하나만 최종 노트 예산에 포함됐습니다. 나머지 슬롯에는 연결되지 않은 후순위 검색 노트가 들어왔습니다. 음성 인용 맥락에서는 관계의 시작·끝 ID와 술어도 허용 목록에서 빠졌습니다. 이는 화면의 연결이 답변 근거로 충분히 전달되지 않은 결함입니다.

0.3.25는 RRF 1위 노트의 실제 outgoing Body Links·`derived-from`을 한 단계만 확장합니다. 방·게시된 corpus 계정 필터를 먼저 적용하고, 유효한 대상만 노트 예산에 넣습니다. 다음 단계의 참조나 같은 디렉터리·이름·분류로 이웃을 만들지 않습니다. 관계 예산에서는 `derived-from`을 먼저 읽어 동일 대상의 본문 링크가 다른 전제를 밀어내지 않게 합니다. 원래 참조·정본·Raw는 수정하지 않습니다.

문자 예산 `B`에서 선택된 관계 문장에 `min(B/3, 관계 문자 합)`을 예약하고, 남은 노트 수로 본문 예산을 나눕니다. 노트·관계의 일부만 들어오면 truncation을 표시합니다. 실제 예산과 포함 노트만 반환하며, 양 끝 노트의 SHA를 재확인합니다. 직접 관계를 묻는 음성 요청은 최대 네 노트·세 관계를 사용하고, 일반 요청은 두 노트·한 관계를 유지합니다.

같은 실제 질의에서 세 전제의 포함 수는 1/3→3/3, 확인 가능한 음성 관계의 양 끝 ID는 0→3쌍이 됐습니다(n=1, 현재 104개 정본 노트). 네 노트와 세 관계의 인용 JSON은 5280자였으며 기존 8000자 한도 안에 들어왔습니다. 로컬 27B는 세 전제의 정확한 제목을 완결된 한 문장으로 반환했습니다. 전체 corpus의 의미 품질을 입증하는 지표는 아닙니다.

## 모델 입력과 기록의 분리

모델 입력에는 안정적인 ID·방향·관계·출처 유형·시점·부분 읽기 표시를 유지합니다. 원문 SHA와 중복된 ID/Raw 좌표는 전체 검색 측정값에 남기고, 정상 완료한 답변과 함께 비공개 `voice_sources`에 원자적으로 저장합니다. 다른 턴의 adapter 측정값이 바뀌어도 생성 직후 복사한 해당 턴의 증거를 기록합니다. 중복 답변은 기존 본문이나 증거를 덮지 않습니다. 음성·원본 DB 데이터는 이 표에 기록하지 않으며 기존 텍스트 이력과 호환됩니다. 사용자가 SHA/출처 좌표를 직접 요청하면 모델 입력에도 전체 증거를 전달합니다.

같은 고정된 일곱 사실·출처·질문, 같은 로컬 27B·temperature 0.3·출력 128토큰을 사용해 전체/축약 메타데이터 요청을 세 번씩 교차 실행했습니다. 이 비교의 요청 시간은 검색을 제외하며, 다른 운영 worker는 유지했습니다.

| 측정 | 전체 메타데이터 | 축약 메타데이터 |
|---|---:|---:|
| 입력 토큰 | 3199 | 1640 |
| 응답 중앙값, n=3 | 0.919초 | 2.659초 |
| 첫 가시 토큰 중앙값, n=3 | 0.490초 | 2.139초 |
| 세 제목 모두 맞은 응답 | 3/3 | 3/3 |

입력 감소율은 `(3199−1640)/3199×100=48.73%`입니다. 지연은 오히려 축약본의 중앙값이 높았습니다. 캐시 토큰은 전체 `[110,3168,3168]`, 축약 `[110,1609,1609]`였고 호스트/대기 부하를 통제하지 않았습니다. 속도 개선·일반 품질·p95·전력 절감을 주장하지 않습니다. 이 한 질의는 개발 시나리오이며 새 독립 최종 평가셋이 아닙니다.

## 검증·복구 범위

실제 SDK를 사용하는 임시 vault 검사는 순위 밖의 세 직접 전제, 700자 본문/관계 예산, 한 단계 제한, 양 끝 SHA, 다른 방·계정 제외와 symlink pointer 거부를 확인합니다. 음성 검사는 관계 ID/해시 보존, 논문 원문 요청의 불필요한 채팅 검색 차단, 명시 SHA 요청, 늦은 측정값 변경과 중복 이력 방어를 포함합니다. 원래 노트와 Raw 바이트는 보존합니다.

설치 검증용 Python import가 앱 내부에 3.14 캐시 9개(739195바이트)를 만들면서 서명 검사가 실패했습니다. 해당 생성물만 비공개 byte backup/SHA 확인 후 제거해 strict/deep 서명과 45개 파일의 정확한 집합·SHA 일치를 복구했습니다. 고정 3.11 배포 바이트코드는 유지했습니다. 재현 스크립트도 bytecode 쓰기를 막으며 설치본 검사는 `-B`로 실행합니다.

여섯 도식의 프로세스·저장·상태 경계는 유지됩니다. [기존 도식의 고정 판본과 영수증](alden-current/README.md)은 이전 구현 SHA에 묶인 기록이며, 직접 참조 예산과 턴별 source 기록의 현재 세부 동작은 이 문서를 사용합니다. 전체 의미·조직 검토, 더 넓은 독립 검색 평가, 물리 음성/primary/Retina/lock/shortcut, Flash-Next, Dot 실제 호출, 같은 조건의 전체 앱 성능, Developer ID·공증·production은 계속 남아 있습니다.
