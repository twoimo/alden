# Dated retrieval observations — 2026-10-09

Previously the fixed “which pricing record is latest?” query included both dated records in top-k candidates and answer context. The older record is not retracted and must remain available for history. There is no explicit supersession edge, so this change does not declare that record invalid, merge its identity, delete it or fabricate a replacement relation.

Explicit latest/most-recent requests now prefer the newest attested observation within each exact query mention. Stored names/aliases establish lexical relevance only. Legacy graph records use recorded confirmation times with evidence IDs; collected sources use recorded publication times; canonical OSK notes use their validated note-revision times. Indexing/collection time is not used as a substitute for a missing source observation date. Text context identifies the timestamp basis and states that it does not prove current claim validity.

History/comparison requests and explicit date-range contracts retain their existing behavior. Unknown, malformed, naive or future dates keep candidates with uncertainty; date-only timezone/within-day uncertainty preserves overlapping candidates. Ambiguous people, distinct publishers with the same label, explicit conflicts, and pinned historical records remain available. These rules run after permission, room, participant, retraction and version filters, and do not expand authorization. Relations cannot reintroduce an observation excluded from latest selection. Canonical actual outgoing-premise expansion and evidence/hash readback remain intact.

The new helper is a required packaged resource. No model/provider/embedding profile changes, new weights, training or original-data changes are needed. Regular relevance queries avoid the additional legacy date/alias metadata lookup.

Fixed synthetic evaluation uses unchanged corpus/queries (20 entities, 13 queries, dev 6 / held-out 7). Actual existing pinned E5 at the same loopback endpoint was used once for each compared implementation. Held-out top-1 Recall remains 0.9 and nDCG 1.0. Whole-context old-record inclusion falls from 1/6 applicable forbidden checks (0.1667) to 0. The broader context Recall remains 0.7; this is not proof of independent real-source quality or latency improvement. Expanded 27-query fixture RRF checks have no violations; BM25 still has its known joined-spacing miss. Query-time timestamps do not attest real-world policy validity, completeness or freshness beyond accessible evidence.

Before/after model and implementation receipts, frozen fixture hashes, isolated product checks, native candidate/installed readback, and delivery status are stored in the private task outputs/retrieval-freshness-20261009 directory. The initial installed-baseline report hit a metadata path-serialization assumption; its log was retained and only the runner's metadata root was repaired. Product grading, thresholds and frozen gold were not changed.

Full independent human-reviewed real-source evaluation, stronger explicit validity/supersession/conflict records, broader multi-host acquisition, physical voice/UI input, immutable active-worker rollout, DPO and production release gates remain part of the active objective.
