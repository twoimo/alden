## 대화 목록 갱신과 입력 대상

음성 대화 기록 목록을 새로 읽었을 때 이전에 선택한 세션이 사라져도 헤더, 메시지와 마이크 시작 버튼의 대화 ID가 남았다. 성공한 전체 목록에서 선택이 없음을 확인하면 세션 ID, 메시지, 페이지 커서와 응답 epoch를 함께 정리한다. 새 목록에 세션이 있으면 해당 세션을 선택하고, 빈 목록이면 다음 명시적 시작에 새 세션을 요청한다. 이미 실행 중인 음성 리스너의 소유권이나 대화를 이 동작으로 바꾸지 않는다.

실패하거나 형태가 잘못된 응답, 부분 목록은 세션 삭제의 근거가 아니다. 기존 요청 세대와 화면 가시성 검사는 계속 적용하며, 오래된 메시지 응답이 다른 선택에 덮어쓰지 못하게 한다. 실제 `voice-history-sessions`는 현재 전체 세션 목록을 반환한다.

실제 `wireConversationViews`와 `wireVoiceStart`를 연결한 가상 데이터 회귀에서 기존 ID 유지와 빈 목록의 ID 유지 두 실패를 재현했다. 독립 검토는 부분 목록이 기존 메시지를 숨기는 실패를 추가로 재현했다. 부분·잘린·다음 페이지가 있는 빈 응답은 기존 목록과 메시지를 보존하고 전체 조회 실패를 표시한다. 초기 부분 응답의 다시 불러오기도 확인했다.

전체 UI 524개, 독립 비동기 귀속 24개, 기존 이력·대화 전환·음성 턴 Python 34개, Rust 119개와 strict Clippy, TypeScript/Vite가 통과했다. 독립 24개는 전체 UI 524개에 포함된다. Rust 첫 병렬 실행은 제한된 메타데이터 probe의 정상 fixture 4개에서 실패했고, 동일 소스의 해당 8개 및 전체 119개를 직렬 실행해 통과했다. 100ms 런타임 상한이나 fallback을 완화하지 않았다. 가상 호출에서 다음 시작에 새 목록의 ID 또는 ID 없는 요청이 전달되는 것을 검증했다. 실제 사람의 음성 시작이나 카카오톡 송신 검증으로 확대하지 않는다.

## 설치와 화면 확인

설치 57개 파일과 모드를 빌드 후보와 대사했고 strict/deep ad-hoc 서명이 통과했다. 모델·등록·중단 설정 3개, 수집 대상 설정 7개, 취득 정책 2개와 로컬 모델 리스너가 이전 상태를 유지한다. 새 bytecode가 생성되지 않았다. 별도 0.3.65 복구 사본과 설치 관리자의 백업을 보존하고 화면 감사 후 동일 검사를 다시 확인했다.

후보와 실제 설치 경로의 읽기 전용 WKWebView 감사는 각각 7개 페이지 × 2개 크기의 14개 상태와 24개 PNG, 오류 0을 기록했다. 영향받은 음성 기록 페이지의 기본·작은 창을 각각 직접 검수했다. 이번 실제 저장소의 음성 기록은 빈 상태였다. 따라서 실제 세션을 제거한 뒤의 전환이나 실제 마이크 시작을 설치 화면에서 재현했다고 표시하지 않는다. 해당 전환·재시도·늦은 응답은 가상 자료를 연결한 실제 UI 모듈에서 검증했다. 물리 입력과 primary 프로세스의 화면 조작은 별도 미결이다.

## 남은 입력 경로

현재 UI는 명시적 음성 시작과 기록 조회를 제공한다. `AldenVoicePipeline.process_text`는 내부 경로이며 텍스트·이미지·파일을 제출하는 UI와 연결되지 않았다. 실제 입력 수신, 내용 접근, 파싱, 검색과 답변 생성의 전체 연결 및 동시 입력 검증이 남아 있다. 내장 마이크의 실제 사람 음성 검증은 덮개 닫힘 상태에서 완료되지 않았다.

원문 중복·이상치·정규화와 의미 군집의 독립 정답 검증, 물리 조작, 여러 호스트, 정식 서명·릴리즈·프로덕션은 전체 목표의 별도 종료 조건으로 유지한다. 기존 라벨 배치와 중앙 분산의 전달 근거를 이 대화 회귀 결과로 대체하지 않는다.
