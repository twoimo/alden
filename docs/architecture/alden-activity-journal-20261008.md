# Committed collection activity — 0.3.31

The read-only `collection-graph` action accepts `activity: true`, permitted projects, optional target/platform, an opaque `stream_id`, an `after` sequence and a budget of at most 200 journal stages. Every graph snapshot carries an `activity_checkpoint` from the same read transaction and target/platform scope, including empty results. It does not create a store, change permissions, migrate data, infer relationships or call a model.

The response advances its cursor across all permitted stages, including skipped stages. Only a `stored` event for an actual document/version, from a completed run, with `change` equal to `added` or `revised` becomes an activity candidate. Each candidate carries event/sequence, source target, document/version, source run/origin, timestamp and explicit success. Unchanged records, evidence-only receipts, parsing/validation/indexing stages, failed/paused runs and denied targets do not become candidates.

Initial attachment, journal replacement, cursor rollback and global first-event pruning return `reset: true` without candidates and require a fresh permitted snapshot. Sequence gaps from other targets do not imply lost history. The first global event identifies the generation; target-only retention without changing that first event is not separately implemented. Existing immutable journal/history storage remains authoritative; visual receipts are transient.

`CollectionActivity` reads one page at a time only while visible: 2.5s cadence, 500ms between catch-up pages. The cursor survives hiding, pending pulses do not. Ordinary snapshots never skip unread pages. Scope changes fence requests and clear cursor/receipts; reset pages require a fresh checkpoint. Late hidden replies cannot commit a cursor or restart rendering. Historical catch-up already covered by the current snapshot avoids redundant full graph reads.

Pulses require a currently visible node with the exact version and target. Occurrence must be after the current visibility start, no later than now and under 10s old. Duplicate IDs, reverse sequences, invalid/over-budget pages and non-progress loops are rejected. Pending admission is capped at120 nodes and remembered IDs at400. Actual source changes coalesce into a graph refresh.

Selection stays warm; a save blends green; a successfully returned, version-checked source detail blends blue. Reading creates no knowledge change. Selection takes color priority; a recent read is blue after the user moves to another node. Colors do not denote model-context use, trust or learning. No arbitrary edge flow is introduced.

Existing slots reuse their color buffer. Intensity is `0.85 exp(-age_ms/1500)` with a10000ms lifetime. Reduced motion uses one static0.65 blend and one expiry timer instead of continuous animation. Hiding clears that timer and color state. The overlay does not change positions, edges, importance or camera; existing bounded physics owns layout changes.
