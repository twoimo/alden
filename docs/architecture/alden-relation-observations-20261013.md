## Relationship versions and observation receipts

All 22,388 current career relationships differed from their preceding evidence only at `source.observed_at`. File SHA and raw edge evidence were identical. The old full-evidence digest therefore added an entire relationship revision cohort during an otherwise identical file replay.

The collector now reuses the previous version only for complete snapshots with matching source revision, validated old history/evidence binding, matching endpoints/type/target, finite positive observation times and exact equality of every other evidence field. Changed file hashes, quotes, authors, paths, direction, type, raw-edge timestamps and non-snapshot changes retain their normal version behavior. Missing edges still deactivate; old history is retained.

An explicit `source_observation` cursor field is validated before publication. `source_observations` stores an immutable deterministic receipt bound to target, source revision, processing version, projection SHA, actual read time, confirmation time, completed basis run and record/relationship counts. Numeric timestamps normalize for integer/float replay identity. Receipt, cursor and last success publish inside the same target lock/guarded transaction. The greatest confirmed timestamp is retained and `source_capture` survives an unchanged confirmation. Read-only APIs do not create this table or migrate data.
