# 연결 군집 병합 후보와 복원 안정성

2026-10-20. 기준 제품 소스 `9a6d50b3a9417e330b4a3feb1d2e6e503718c736`, 감사 기반 HEAD `f52472b47223604e6aca8e3beaa06ae4de916612`. 설치본은 0.3.191이다. 이번에는 [앞선 채널 감사](graph-channel-audit-20261020.md)의 과분할·간선 복원 반례를 줄이는 **가역적 후보를 구현**했다. 제품 엔진·기본 설정·원문·ID·출처·벡터·설치본을 변경하지 않았다. 전체 18개 목표와 외부 3단계 교차감사는 계속 미완료다.

## 구현과 승격 기준

[후보](audits/connected_aggregate_candidate.ts)는 두 부분으로 구성된다. 변경에 영향받은 연결 요소에서는 현행 노드별 이동을 singleton부터 다시 계산한다. 좌표 캐시·고정 노드·기존 군집 이름의 overlap 재사용은 현행 엔진에 맡긴다. 이어서 같은 군집 안에서 실제 연결이 끊긴 부분을 분리하고, 연결된 군집 쌍을 통째로 병합할 때 현행 component modularity가 증가하는 경우만 합친다. 서로 겹치지 않는 병합을 최대 8회 수행하며, 상한에 도달하면 수렴했다고 표시하지 않는다.

군집 A/B 사이 가중치 합을 w, 두 군집 차수 합을 kA/kB, 해당 연결 요소의 전체 차수 합을 V라 하면 병합의 변화는 `ΔQ = 2(w - kA*kB/V)/V`다. [Blondel 등의 원 논문](https://arxiv.org/html/0803.0476v2)의 modularity 정의·군집 집계 단계를 참고하되, 기존 component 분모를 유지하는 제한된 병합 후보다. Louvain/Leiden 전체 구현이나 계층형 의미 정답으로 부르지 않는다. [Leiden 원 논문](https://arxiv.org/abs/1810.08473)은 Louvain의 연결성 문제와 별도의 refinement 보장을 구분하므로, 이 후보에는 그 보장을 전용하지 않는다.

[후보 빌더](audits/build_connected_aggregate_candidate.mjs)는 실제 현행 엔진의 정확히 일치하는 두 소스 위치에만 audit 변형을 적용한다. 원본 파일을 수정하지 않고 실행 소스·helper·생성기·번들의 SHA-256을 평가 전에 고정한다. anchor가 달라지면 실패한다. product 옵션·저장 형식·모델/임베딩·해상도 파라미터를 추가하지 않는다. 미변경 요소는 후보의 소유 범위 밖에 둔다.

승격에는 목적함수·연결성·기존 입력 및 고정 노드 보존뿐 아니라 실제 의미/동일성/시간 gold, 독립 입력, 배치 변화와 계산 비용의 제품 경로 검증, Gemini 반대감사·ChatGPT reverse가 필요하다. 군집 수가 줄었다는 이유만으로 채택하지 않는다.

## 실제 실행 결과

같은 생성기의 새 크기 **128/256**, 새 seed **601..603**, 5조건·3채널을 기준/후보로 각각 **90조건** 실행했다. 고유 입력은 **66개**, 크기·seed 가족은 **6개**다. 각 조건은 최초·배열 역순·ID치환·3간선 추가·원복의 실제 엔진 호출을 포함한다. 새로운 도메인이나 독립 인간 holdout으로 해석하지 않는다. 결과를 본 뒤 후보나 파라미터를 재선택하지 않았다.

[독립 검산](audits/compare_connected_aggregate.py)은 같은 admitted 간선/가중치, 생성 라벨, 원본 partition과 입력 해시를 대사한다. iGraph의 연결 요소별 modularity와 기존 Fraction ARI로 검산했다. 결과 전체와 동결된 실행 소스는 `outputs/connected-aggregate-20261020/`에 있다.

- 90조건 모두 군집의 실제 연결성을 유지했고, 원래 그래프로 되돌리면 최초 partition과 ARI 1이었다. 기준은 41조건에서 복원 ARI가 1보다 작았다. 군집 이름 문자열이나 좌표까지 원복된다는 보장은 아니다.
- component modularity는 29조건에서 증가하고 나머지에서 유지됐다. 원래 생성 구조 라벨 ARI는 29조건에서 증가하고 나머지에서 유지됐지만, **다른 생성 유사도 라벨 ARI는 2조건에서 낮아졌다**. 두 생성 라벨이 모순되는 경우 구조 목적함수 개선을 의미 정답으로 볼 수 없다.
- **ID치환 안정성은 10조건에서 나빠졌다.** 정렬 tie 순서 의존성은 해결되지 않았다.
- 배열 역순 결과·유한 좌표·고정 노드 보존, 모든 후보 pass/방문 상한을 대사했다. 추가 병합 방문은 `2 × admitted pairs × (8+1)` 이하다. 이번 90조건에서 병합 상한 종료는 0이었지만 별도 2,048노드 star 반례는 8회 상한 종료를 명시적으로 재현했다.

## 판정과 남은 작업

| ID | 판정 | 구현·근거 | 다음 gate |

후보의 입력은 임의 장식 노드나 사실 관계가 아니다. 합성 평가 자료와 실제 저장소를 분리했으며 원문·ID·관계·병합 overlay에 쓰지 않았다. 표시 군집 병합을 동일 실체 병합이나 중복 삭제로 해석하지 않는다.

## 검증·전달 범위

후보 helper 7개 회귀에는 직접 O(n²) 목적함수 정의로 모든 단순 5노드 그래프 1,024개를 검산하는 조건, 무관 요소 불변, 2,048노드 ring/star의 작업 상한이 포함된다. 전체 UI **1,010검사/90파일**과 strict TypeScript가 통과했다. 잘못된 bundle hash와 변조된 ARI를 넣으면 verifier는 보고서를 만들지 않고 거부했다. 전체 UI는 현행 제품과 helper의 회귀이며, 후보 변형 엔진의 전체 제품 인증은 아니다.

QA는 전면/floating 앱 창 없이 실행했다. 실제 앱 최소화 상태·GPU/FPS·배터리·물리 입력은 이 실행에서 측정하지 않았다. 새 테스트 파일 때문에 기존 canonical build 입력 영수증은 더 이상 현재 소스와 일치하지 않는다. 영수증을 다시 쓰거나 우회하지 않았으며, 다음 실제 빌드는 정상 canonical 경로로 새 입력을 검증해야 한다. 설치본은 별도로 기존 77파일 manifest/mode와 strict deep 서명을 대사해 보존 여부를 확인한다.

재현 시 기존 출력 폴더를 덮어쓰지 말고 새 두 폴더를 사용한다. 생성된 `build.json`을 유지한 채 각 `channel-audit.mjs --sizes 128,256 --seed-start 601 --seed-count 3` 출력을 `inputs.json`으로 저장한다. builder의 `--mode baseline`/`candidate`와 `--out <새 폴더>`를 각각 실행한 뒤, 기존 격리 Python runtime에서 `-B docs/audits/compare_connected_aggregate.py --baseline <기준 inputs.json> --candidate <후보 inputs.json> --output <새 결과.json>`을 실행한다. 공개 저장소에 대형 입력 복사본·runtime·원문 사용자 데이터·저장소 archive를 첨부하지 않는다.
