# Retained graph-note reading boundaries

A retained graph note ending with the existing numeric-tail pattern could be folded for reading when its lines used LF, but the same note using CRLF or CR stayed unfolded. The splitter discarded the separators, and rebuilding the prefix with LF made the exact retained-prefix check fail.

The backend reading presentation now keeps each original separator while locating the boundary. The popup also compares a projection against the exact retained string before its ordinary trimming fallback. Previously outer indentation or a trailing line ending made an otherwise valid projection fail the UI equality check. Inputs needing control-character removal or exceeding the 12,000-character UI budget still cannot hide content behind a fold. The numeric-tail policy, uncertainty label and source binding remain the same. It does not alter stored bodies, source bytes, IDs, versions, indexing, duplicate decisions or entity merges. The complete original stays available through the existing expanded view.

The new regression failed in four CRLF/CR subcases before the change. Six LF/CRLF/CR and trailing-blank-line cases now preserve the exact reading/tail concatenation. A collection detail integration test also preserves the database, source blobs, indexed rows and current version. The affected source/collection/retrieval/quality suites passed 175 tests. Three new UI examples failed before the popup change; the final full UI suite passed 94 files / 1,058 tests, including unchanged popup lifecycle and source integrity checks. A cross-language probe fed installed-module detail payloads from an isolated collection into the previous and candidate production DOM renderers: all three old presentations failed to fold, while all three candidates folded and expanded to the exact retained text. This is DOM behavior evidence, not native visual/layout verification.

A read-only snapshot verified 25,157 permitted graph raw-version references (19,025,727 bytes), including 12,538 retained text bodies. None contained CRLF or lone CR. All 42 existing reading folds were identical before and after the patch. A second snapshot had the same source-reference signature; none of those 42 contained outer whitespace, stripped controls or a body beyond the UI UTF-16 budget. This is a reproducible boundary defect, not evidence that it caused the user's current screenshot or that the live corpus had that defect.
